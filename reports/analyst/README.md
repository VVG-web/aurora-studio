# Отчёт «Эффективность аналитиков»

Один самодостаточный HTML: недельная активность по Jira и Confluence, переходы задач
по статусам, фильтры по типу задачи и по человеку. Открывается файлом, без сервера.

```bash
python3 .opencode/scripts/report_analyst.py                # выгрузить и собрать
python3 .opencode/scripts/report_analyst.py --skip-fetch   # собрать по выгруженному
```

В панели — `ops:report`.

## Настройки

Проектных констант в скриптах нет: всё приходит из `aurora.config.yaml`.

```yaml
reports:
  analyst:
    year: 2026                              # какой период открыт при загрузке
    # years: [2024, 2025, 2026]             # ограничить набор (иначе — по данным)
    roster: Settings/report-roster.csv      # ФИО;Email;Роль;Прежние ФИО
    events: Settings/report-events.csv      # weeks;name;caption;severity
    data_dir: .opencode/cache/reports/analyst
    output: Artifacts/reports/{project}_analyst_extended.html
```

Секции может не быть — тогда работают эти же значения по умолчанию. Адреса Jira и
Confluence, ключ проекта и пространство берутся из `atlassian:`, имя проекта — из
`project.name`.

## Периоды

Проект живёт дольше календарного года, поэтому отчёт собирается **по каждому году
сразу** и несёт их все в одном файле: переключатель периода стоит в шапке дашборда,
пересобирать ради смены года ничего не нужно. Годы определяются по самим данным — по
истории статусов Jira и датам страниц Confluence.

`year:` задаёт период, открытый при загрузке; `years:` — ограничивает набор, если в
выгрузку попала предыстория, которую смотреть незачем.

Выгрузка при этом одна на все годы: сырьё от периода не зависит, и переключение
периода не стоит нового похода в Jira и Confluence.

## Как считается тренд

Линия тренда строится не по всей оси, а по рабочему окну — от первой недели с
активностью до последней. Иначе она говорит неправду в двух местах:

- **начало года до старта проекта.** Проект, поехавший в июле, приносит на ось
  полгода нулей, и наклон тем круче вниз, чем позже стартовал проект. Два одинаково
  работающих проекта получали бы разный «тренд» только из-за даты старта;
- **конец года, который ещё не наступил.** Пока год идёт, оставшиеся недели — это
  будущее, а не спад.

Текущая неделя в подгонку тоже не входит: она ещё не кончилась, и её неполный
столбик каждый раз тянул бы линию вниз просто потому, что сегодня среда.

### Ростер

`Прежние ФИО` — старые написания имени одного человека (смена фамилии). Jira хранит
в истории назначений ФИО на момент события, поэтому без склейки один сотрудник
распадается на две строки отчёта. Разделитель — запятая или точка с запятой, как
сохранил Excel; читается и то и другое.

### События

Полосы на графике: `weeks` — номера недель через запятую (`6` и `06` равнозначны),
`caption` — подпись, `severity` — насколько заметно рисовать.

## Доступы

`JIRA_PERSONAL_TOKEN` и `CONFLUENCE_PAT` — в `.env.aurora.local` (он в `.gitignore`).
В `aurora.config.yaml` токены не пишутся.

## Цепочка

| Шаг | Что делает | Пишет в кэш |
|---|---|---|
| `fetch_issues.py` | список задач по JQL | `issues.json` |
| `fetch_subtasks.py` | подзадачи выгруженных задач | `issues.json` |
| `fetch_full.py` | история статусов и назначений | `full_status.json` |
| `fetch_confluence_metadata.py` | страницы пространства | `confluence_raw_metadata.json` |
| `process_confluence.py` | недельная активность по людям | `by-year/‹год›/confluence_activity.json` |
| `make_analyst_metrics.py` | переходы и недельные суммы | `by-year/‹год›/analyst_metrics.json` |
| `update_analyst_metrics.py` | события BA-SA Task | то же |
| `verify_weekly_by_person.py` | сверка сумм по людям с общими | то же |
| `make_extended.py` | сборка HTML из всех годов | отчёт |

Четыре шага выгрузки идут один раз, четыре шага счёта — по разу на каждый год.

`serve_dashboard.py` нужен только затем, чтобы кнопки в дашборде открывали файлы
настроек в редакторе и запускали пересборку. Без него дашборд работает, а кнопки
кладут готовую команду в буфер обмена.

# ADR-026. Исполняемое содержимое проекта: доверие к ките, без подтверждений

## Контекст и проблема

Проект — git-репозиторий, команда работает через несколько клонов. Часть содержимого исполняется
на машине участника: боты (`bots/*.md`), скрипты движка в `.aurora/scripts`, определения серверов
MCP. Ревью 08.10.2026 предложило подтверждение владельцем машины для всего такого содержимого
(реестр согласий по хешу), и 09.10.2026 это было принято как решение Q-08.

При реализации (BL-SEC-04, 10.10.2026) подтверждение оказалось вредным: проектные копии скриптов
движка почти всегда отстают от кита, и панель просила одобрить «изменённые» файлы, которые на самом
деле кит же и поставил. Проверить, что одобряешь, невозможно, не читая код, а читать его никто не
будет. Подтверждение мешало работе, путало и не защищало.

## Факторы решения

* Скрипты кита доверенные по определению: их поставляет сам продукт.
* Защита от вредоносного кода — задача кита (в нём только полезные скрипты), антивируса и
  гигиены репозитория, а не диалога с человеком.
* Подтверждение, которое нельзя осмысленно проверить, создаёт ложное чувство безопасности.
* Команда небольшая, репозитории закрытые; доверие к коллегам — исходное условие работы.

## Рассмотренные варианты

1. **Реестр согласий владельца машины по хешу** (прежний Q-08). Реализован и снят: см. выше.
2. **Подпись коммитов.** Тяжело для небольшой команды.
3. **Доверие кита без подтверждений.** Выбранный вариант.

## Решение

Выбран вариант 3.

1. **Согласий нет.** Боты и скрипты проекта запускаются как раньше: ни по расписанию, ни по кнопке,
   ни из консоли их не останавливает вопрос «одобрить?». Реестра `~/.aurora/consent.json` нет.
2. **MCP-серверы настраиваются один раз на уровне кита** (как модели): определения (команда,
   аргументы, окружение, токены) читаются только из `<кит>/local/mcp.json`. Проектный `mcp.json`
   серверы не определяет и не перекрывает серверы кита; `doctor` и панель предупреждают «файл не
   используется». Проект выбирает серверы кита по имени (`mcp: servers:` в `aurora.config.yaml`);
   неизвестное имя — ошибка до запуска. Перенос серверов из проекта в кит — по показу различий и
   с подтверждением человека в окне переноса (это не согласие на исполнение, а защита от потери
   настройки).
3. **Право записи во внешние системы** (Jira `jira_write`) выдаёт кит (`permissions` в
   `local/mcp.json`); `jira_write: true` в `aurora.config.yaml` проекта его не включает, проект
   может только сузить.
4. **Хуки git** остаются защитой от публикации внутренних названий (ADR-066 и BL-SEC-14), а не
   подтверждением исполнения.

## Последствия

* Плюс: нет лишних диалогов, панель и ночные цепочки работают без остановок на «ждёт согласия».
* Плюс: проектные скрипты, отставшие от кита, больше не маркируются как «чужие».
* Минус: клон чужого репозитория может принести бот или скрипт, которые выполнятся с токенами
  владельца. Принято: открывать чужие репозитории в Авроре без проверки не следует, как и в любой
  среде разработки.
* Риск: проектный бот может обратиться к инструментам кита. Ограничение — набор серверов и право
  записи задаёт кит, а не проект.

## Проверка

* Тест: бот и проектный скрипт из git запускаются без какого-либо подтверждения.
* Тест: проектный `mcp.json` не меняет набор серверов агента и не передаёт токены.
* Тест: `jira_write: true` в проекте не включает запись.
* Тест: прогон тестов не видит настоящий `~/.aurora` владельца.

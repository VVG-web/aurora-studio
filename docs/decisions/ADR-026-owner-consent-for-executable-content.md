# ADR-026. Согласие владельца машины на исполняемое содержимое проекта

## Контекст и проблема

Проект — это git-репозиторий, и команда работает через несколько клонов. Часть его содержимого
исполняется на машине каждого участника: боты (`bots/*.md`), запускаемые по расписанию и по
кнопке, определения серверов MCP в проектном `mcp.json`, настройки политики и скрипты проекта.
Изменение такого файла у одного участника при обычном `git pull` у другого становится запуском
чужой команды без его ведома. Проектный `mcp.json`, кроме того, может подменить по имени сервер,
заданный на машине.

Владелец решил (Q-08, 09.10.2026): новое или изменённое исполняемое содержимое **не запускается без
согласия владельца машины**, согласие привязано к хешу.

## Факторы решения

* Репозиторий не должен давать исполнение на чужих машинах без подтверждения.
* Команда небольшая: подпись коммитов и инфраструктура ключей — слишком тяжело.
* Согласие не должно ломать работу с привычными ботами: подтверждается один раз на содержимое.
* Решение должно работать офлайн и в закрытом проекте.

## Рассмотренные варианты

1. **Ничего не менять:** определения из git исполняются сразу. Просто, но небезопасно.
2. **Подпись коммитов и проверка подписи.** Сильная гарантия, но тяжело для небольшой команды.
3. **CODEOWNERS на `bots/`.** Защищает только на платформе git, не на машине участника.
4. **Реестр согласий по хешу на машине.** Выбранный вариант.

## Решение

Выбран вариант 4.

1. **Реестр согласий** хранится в состоянии пользователя на его машине, не в репозитории: проект,
   путь определения, SHA-256 содержимого, кто и когда согласился.
2. **Что подпадает:** боты проекта, серверы MCP из проектного `mcp.json`, определения расписания и
   политики, скрипты проекта, которые запускает движок.
3. **Неодобренное или изменённое** определение (хеш не совпал с записью) **не запускается** ни по
   расписанию, ни по кнопке, ни из консольной команды; в разделах Cron и «Боты» оно помечено, а
   причина названа текстом.
4. **Согласие даёт владелец машины** явным действием (кнопка в панели или команда). Автоматика,
   ассистент и ночная цепочка согласие не дают.
5. **Сервер проекта не подменяет сервер машины:** проектный `mcp.json` может добавить сервер, но не
   заменить команду одноимённого машинного сервера без отдельного согласия.
6. **Запись в журнал** (событие согласия и отказа запуска) — вместе с общим журналом действий.

## Последствия

* Плюс: клон чужого репозитория или `git pull` от коллеги не запускают незнакомый код.
* Плюс: ночные цепочки не выполняют изменённого без ведома владельца.
* Минус: лишнее подтверждение после каждого изменения бота — особенно у автора, который правит
  бота каждый день; нужен быстрый путь «одобрить свои изменения».
* Минус: защита от владельца машины, который согласился не глядя, отсутствует; это согласие, а не
  изоляция.
* Риск: старые проекты при первом запуске получат запрос на все существующие определения;
  нужна пакетная кнопка «одобрить текущее состояние» с показом списка.

## Проверка

* Тест: бот с неодобренным хешем не запускается ни одним из трёх путей (расписание, кнопка,
  командная строка), а после согласия запускается.
* Тест: изменение одного байта определения снимает согласие.
* Тест: проектный `mcp.json` не заменяет команду одноимённого машинного сервера.
* Тест: ночная цепочка и ассистент не имеют пути к выдаче согласия.

# 4. Практика: команды и промпты

> **Кому читать:** всем, кто выполняет операции с базой.
>
> Есть два пути. Через ассистента в репозитории — командами `/aurora-vault`. Или руками —
> запуская скрипты движка напрямую и пользуясь заготовками из `Prompts/` в любом чате.

## Ситуация → команда

| Ситуация | Команда | Результат |
|---|---|---|
| Прошёл синк Confluence или Jira | `sync:diff` | дрейф: какие проверенные карточки могли устареть, по владельцам |
| Целостность зеркала под вопросом | `sync:audit` | missing / orphan / collision, протухшее состояние синка |
| Задачи закрываются, а требования нет | `sync:jira-status` | кандидаты в `implemented`, работа без требований, истории без задач |
| Надо проверить качество истории или критериев | `make:review <объект>` | вердикт и замечания с цитатами карточек, которым текст противоречит |
| Надо написать историю, критерии, спеку | `make:create <тип> <тема>` | черновик по шаблону с перечнем использованных карточек в `based_on` |
| Спеку пора отдать подрядчику | `make:spec-pack <SPEC-NNN>` | самодостаточный бандл: основания, решения, аббревиатуры, риски передачи |
| Приняли решение или сменили подход | `kb:decide <тема>` | Decision Record; старый помечен `superseded`; список карточек к обновлению |
| Карточка устарела, есть замена | `kb:supersede <карточка>` | старая в архив со ссылкой на преемника, входящие ссылки переписаны |
| Положили закон, регламент, ТЗ в `Raw/` | `kb:ingest-raw <путь>` | карточки-кандидаты `imported` и список возможных дублей |
| Прошла встреча с заказчиком | `kb:ingest-meeting <транскрипт>` | резюме с цитатами, кандидаты в решения, требования и факты |
| В `Raw/` лежит docx, pdf, xlsx | `kb:ingest-office` | markdown-транскрипты рядом с оригиналами |
| Кандидаты готовы к приёму | `kb:verify <раздел> --owner @вы` | гейт: владелец, срок годности, отказ при битых ссылках |
| Непонятно, что проверять первым | `kb:queue` | очередь по ценности: употребление, связи, протухание |
| Нужен проверенный контекст для запроса | `ctx:context <тема>` | подборка карточек с шапками доверия — вставляется в любой промпт |
| «Почему выбрали X? Почему не Y?» | `ctx:ask <вопрос>` | ответ с цитатами, включая отклонённые и заменённые решения |
| Механика базы поехала | `kb:repair` | битые ссылки, гомоглифы, легаси-шапки; сначала предпросмотр |
| Схема карточки поменялась с версией kit | `kb:schema` | сколько карточек на какой версии и что сделает миграция |
| Пятничная гигиена | `kb:garden` | просроченное, сироты, битые ссылки, дубли; задачи по владельцам |
| Общее состояние базы | `ops:stats` | дашборд: статусы, доля проверенного, риски |
| Кто на кого опирается | `ops:impact <карточка>` | что сломается при изменении; `--explain` — на чём собран документ |
| Где разрывы в трассировке | `ops:trace` | пункт ТЗ → требование → спека → задача → критерии → приёмка |
| Артефакт готов к публикации | `ship:publish <файл>` | generated-страница в Confluence; правки на ней будут потеряны при следующей публикации |
| Документ надо отдать в офисном формате | `ship:export <файл>` | docx или pdf через pandoc |
| Версию передали заказчику | `ship:release <документ>` | неизменяемый снапшот в `Deliverables/released/` |
| Не помню, какие вообще есть команды | `kit:list` | справочник: модификаторы, чем исполняется, с какой версии |

Полный список с модификаторами — [`docs/commands.md`](../commands.md) или
`python3 aurora.py list <проект>`. То же самое в панели: `python3 aurora.py cockpit`.

## Правило запуска

Команды движка делятся на две категории, и это видно по флагам.

**Наблюдение** — `stats`, `lint`, `queue`, `impact`, `trace`, `audit`, `diff`, `schema`,
`scrub`, `classify`. Запускаются свободно, ничего не меняют.

**Запись** — всё, у чего есть `--apply`: `repair`, `retire`, `verify`, `supersede`,
`index`, `release`, `update`. Без флага такая команда делает предпросмотр и показывает,
что произойдёт. Смотрите предпросмотр всегда: массовая правка по базе — это то, что потом
разбирается в `git diff` часами.

**Наружу** — `sync:*`, `ship:publish`, `ship:export`. Нужны сеть и токен, меняют внешние
системы. Токены живут в `.env.aurora.local`, в git не попадают.

## Ручной путь: промпты

Для работы вне репозитория — в веб-чате или другом инструменте — есть заготовки в
`Prompts/`. В шапке каждой указано, какой шаблон использовать и куда класть результат.

| Промпт | Назначение |
|---|---|
| `US_review_with_KB.md` | проверка истории или критериев с контекстом базы |
| `DR_create.md` | оформление Decision Record интервью-методом |
| `US_create.md`, `AC_new.md`, `AC_update.md` | производство и доработка историй и критериев |
| `SPEC_create.md` | спецификация фичи из требований и проверенных знаний |
| `confluence_upload.md`, `jira_upload.md` | публикация согласованного артефакта |

Правило для ручного пути то же, что и для команд: **сначала соберите контекст**
(`ctx:context <тема>`), не скармливайте ассистенту страницы Confluence как истину. Разница
между «карточка со статусом `verified` и датой проверки» и «страница из вики» — это вся
разница между фактом и слухом.

## Что делать, когда команда ругается

Скрипты движка стараются объяснять причину, а не просто падать. Три частых случая:

**«git-guard: незакоммиченных файлов N».** Массовая запись по грязному дереву делает откат
невозможным. Закоммитьте текущее — или, если понимаете риск, добавьте `--allow-dirty`.

**«нет токена — задайте CONFLUENCE_PERSONAL_TOKEN».** Скрипты синка ходят в Confluence и
Jira напрямую, MCP в редакторе им не помогает. Скопируйте образец
`aurora.env.local.example` в `.env.aurora.local` и заполните два поля.

**«папки верхнего уровня вне схемы».** Кто-то завёл свою папку. Содержимое переносится в
`Workspaces/<задача>/`, либо папка закрывается `.gitignore`, если это служебное.

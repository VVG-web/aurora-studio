# Код проекта: папка `Code/` и раздел «Код»

English: [en/code-room.md](en/code-room.md).

Аврора умеет держать рядом с базой знаний **клоны репозиториев кода** проекта. Код — не знание и не
документ аналитика: это доказательство того, *как система сделана*. По нему движок узнаёт ревизию,
языки и размер репозитория, строит индекс и отвечает на вопросы «где это сделано». Проверка критериев
приёмки истории по коду и «Чистая комната» — следующие выпуски.

Этот выпуск даёт папку `Code/`, реестр репозиториев, раздел панели «Код», синхронизацию, индекс кода
и поиск по нему: `code:sync`, `code:status`, `code:index`, `code:find`. Модель не вызывается нигде:
индекс и поиск работают на стандартной библиотеке и SQLite.

## Папки

| Папка | Что в ней | Кто пишет | В git проекта |
|---|---|---|---|
| `Code/<имя>/` | клон одного репозитория кода, только для чтения | `code:sync` | **нет** — правило `Code/*` в `.gitignore`; в git только `Code/README.md` и `Code/.gitkeep` |
| `CleanRoom/` | артефакты по коду, устроена как `Artifacts/` (папки видов документов появятся вместе с «Чистой комнатой») | движок | да |
| `CleanRoom/Backlog/` | оглавление артефактов по коду в форме бэклога; заполнит движок, когда появится «Чистая комната» | движок | да |
| `Artifacts/Backlog/` | бэклог, который ведёт человек: один файл | человек | да |

Код в git проекта не кладётся сознательно: он большой, у него своя история, свои секреты и своя
лицензия, а два источника правды разошлись бы. Воспроизводимость даёт реестр: адрес, ветка и
закреплённая ревизия записаны в `aurora.config.yaml`, и каждый участник получает те же клоны своим
`code:sync`. Клон, всё-таки попавший в индекс git проекта (до правила или через `git add -f`), —
ошибка `kit:doctor` с командой починки `git rm -r --cached Code/<имя>`. Папка в `Code/` без записи в
реестре и репозиторий в реестре без клона — замечания `kit:doctor`.

«Файлы» не разворачивают клоны (один клон — десятки тысяч файлов): видно описание папки, а сами
репозитории — в разделе «Код». Запись в `Code/` из панели закрыта: правку сотрёт следующая
синхронизация, код правят в его репозитории.

### Бэклог человека: `Artifacts/Backlog/`

Один файл в Markdown, заготовка — `Templates/backlog_template.md`:

```markdown
# Структура

## Activity 1 Приём заявок

### Epic 1.1 Регистрация заявки

* US-1.1.1. Приём заявки от поставщика [ALG-010, CON-001] ([PRJA-101](https://jira.example.com/browse/PRJA-101))
```

`## Activity <код> <название>` — активность, `### Epic <n.m> <название>` — эпик, строка
`* US-<n.m.k>. <название> [коды артефактов через запятую] ([KEY-N](ссылка на задачу))` — история;
коды артефактов и задача необязательны. С этим файлом движок сверит оглавление по коду
(`CleanRoom/Backlog/`): чего в коде нет и что в коде есть сверх бэклога. Разбор файла — в следующих
выпусках; форма записана уже сейчас, чтобы бэклог можно было начинать вести.

## Реестр репозиториев: `code_repos:`

Блок в `aurora.config.yaml` правится **только формой** раздела «Код»: форма отправляет слепок
реестра, который прочитала, и если блок изменили в другом месте (вторая вкладка, `git pull`, правка
руками), запись не проходит (409), а форма предлагает «Взять с диска» или «Записать моё поверх».
Переписывается только этот блок: метка порядка байтов, окончания строк, комментарии и соседние
разделы конфига остаются байт в байт. Форма настроек проекта блок не знает и переносит целиком.

```yaml
code_repos:
  order-intake:
    url: "https://git.example.com/team/order-intake.git"
    provider: "generic"
    branch: "main"
    pin: ""
    include: ""
    exclude: "**/generated/**, *.min.js"
    access: "vpn:VPN-1"
    models: false
    publish: false
```

| Поле | Что значит |
|---|---|
| имя записи | имя папки клона `Code/<имя>`: латиница, цифры, `.`, `_`, `-`, с буквы или цифры, до 64 знаков; имена Windows (`con`, `aux`, `nul`…) запрещены; уникально без учёта регистра |
| `url` | адрес клонирования **без логина и пароля** (пароль в адресе — отказ с советом; логин убирается сам): `https://…`, `git@…:…`, `ssh://…`, путь или `file://` |
| `provider` | `github`, `gitlab`, `bitbucket`, `gitea` или `generic` — как в «Git проекта»; по адресу угадывается сам |
| `branch` | за какой веткой следить; пусто — ветка по умолчанию на сервере |
| `pin` | закреплённая ревизия: SHA (7–40 знаков) или тег; пусто — клон идёт за веткой |
| `include`, `exclude` | маски путей через запятую: что считать кодом сверх умолчаний и что не считать (`**` — любые папки, маска без `/` — по имени на любой глубине) |
| `access` | как до репозитория достать: пусто (как всегда), `internet`, `local` или `vpn:<профиль>` — для проверки соединений |
| `models` | можно ли отдавать код этого репозитория моделям; **по умолчанию нельзя** |
| `publish` | можно ли публиковать артефакты по этому коду; **по умолчанию нельзя** |

### Вход

Как в разделе «Git»: строка `git clone` со страницы репозитория вставляется целиком, провайдер,
адрес и ветку разбирает движок; способ входа — как настроен git на машине, токен, логин и пароль
или SSH-ключ. Секрет лежит **вне проекта**, в `~/.aurora/git/credentials.json` (права 600) под
ключом — полным путём клона `Code/<имя>`; наружу отдаётся только маска. Токен не пишется ни в
конфиг, ни в адрес, ни в командную строку git: git получает его из окружения через помощника
учётных данных. Сменился сервер в адресе — сохранённый токен на новый сервер не переезжает, его
вводят заново. Репозиторий убран из реестра — его вход стирается.

**bitbucket.org:** логин — имя пользователя (не e-mail; оно стоит в строке клонирования), вместо
пароля — API-токен с правом чтения репозиториев.

### Код и модели

Владелец решил: фрагменты кода уходят моделям **только по разрешению у каждого репозитория**
(переключатель «Можно отдавать код моделям», по умолчанию выключен). Пока разрешения нет, файлы
клона не видят ни инструменты чтения ассистентов («Спросить», боты, производство), ни вложения
задания (`@Code/…`), а в подсказки поля запроса папка `Code/` не попадает вовсе. Описание папки
`Code/README.md` клоном не считается.

## Команды

### `code:sync`

Клонирует новые репозитории реестра и обновляет склонированные: забирает свежее с сервера
(`fetch`) и ставит рабочее дерево на закреплённую ревизию или вершину ветки сервера **без ветки**
(`checkout --detach`). Ничего не сливает и не отправляет. Клон — с `core.autocrlf=false` (байты как в
репозитории) и `core.longpaths=true` (Windows); большие двоичные файлы LFS не тянутся.

- **Без `--apply` — план**: что склонируется и куда встанет; в сеть команда не ходит и ничего не пишет.
- Переписанная на сервере история — не ошибка: клон просто встаёт на новую цель.
- **Клон с правками** (правленые или новые файлы) и **клон другого адреса** команда не трогает и
  называет причину. «Сбросить клон» (`code:sync --reset --repo <имя> --apply`) возвращает клон к
  реестру: адрес — из реестра, правки и лишние файлы клона — прочь. Только для одного репозитория.
- **Проверка соединений**: репозиторий, чей профиль VPN (или интернет) сейчас недоступен,
  пропускается с точной причиной и машинной строкой `AURORA-NET`, остальные синхронизируются; код 2
  говорит маршруту и Cron, что шаг не сломался, а ждёт связь. Перед запуском из панели нужды команды
  складываются по всем репозиториям (вычисляемый источник «код»).
- Состояние — `.aurora/state/code/sync.json` (вне git): когда, что сделано, ревизия, языки и размер.
- Пустой реестр — одна строка и код 0: шаг маршрута «Обновить базу» (после `sync:web`) в проекте без
  кода ничего не делает.

Коды возврата: 0 — всё синхронизировано, 1 — часть репозиториев не синхронизирована (причина у
каждого; маршрут идёт дальше), 2 — сбой выполнения или отказ проверки соединений.

### `code:status`

Без сети: по каждому репозиторию — состояние клона, ревизия и её дата, отставание от ветки сервера
на момент последнего обновления (у закреплённого — насколько ветка ушла вперёд), последняя
синхронизация, разрешения и **языки и размер**. Стек репозиториев заранее неизвестен — движок
определяет его сам: язык — по расширению и имени файла, строки — по переводам строк, без внешних
инструментов. Не считаются кодом и называются отдельно: чужие зависимости (`node_modules/`,
`vendor/`, `build/`, `dist/`, `target/`…), сгенерированное (`_pb2.py`, `.pb.go`, заголовок
«Code generated … DO NOT EDIT»), минифицированное, файлы блокировок, двоичное, файлы с секретными
именами (`.env*`, `*.pem`…) и файлы больше 512 КБ. Самый длинный путь клона, который не поместится
на Windows без длинных путей, отмечается.

### `code:index`

Строит или обновляет индекс кода в `.aurora/cache/code/<имя>/index.sqlite`. Читаются **объекты git**
(`ls-tree`, `cat-file`), а не рабочая папка: `core.autocrlf`, символические ссылки, регистр имён и
длинные пути Windows не меняют результат. Без `--apply` — план: ревизия и число файлов, без записи.

- **Инвентарь:** путь, blob, язык, роль (`src`, `test`, `config`, `migration`, `doc`, `generated`,
  `vendor`), размер, строки, кодировка. Зависимости, сгенерированное, минифицированное, блокировки,
  двоичное и секретные имена не разбираются и называются причиной.
- **Что извлекается:** символы (классы, функции, методы, поля, константы), маршруты, таблицы и
  колонки SQL, топики, ключи конфигурации, строковые константы, тесты и метки требований.
- **История:** коммиты, файлы, переименования и ключи только из известного проекту списка
  (`jira_keys` и `project_key`); авторы не сохраняются.
- **Секреты:** значения не пишутся ни в индекс, ни в журналы; строка с находкой маскируется, правило
  и номер строки видны в `--secrets`.
- **Повторный прогон** не читает неизменённые файлы (blob и версия извлекателя те же), прерванный
  продолжается с места остановки. `--rebuild` удаляет индекс и строит заново.
- Пределы: 300 000 файлов в инвентаре, 60 000 разбираемых, 512 КБ на файл; лишнее помечается
  `over_limit` или `too_big`, а не пропадает молча.

### `code:find`

Ищет по индексу: символы, файлы, маршруты, таблицы и колонки, топики, конфигурацию, строки, тесты,
метки требований и коммиты. `--kind` сужает вид, `--limit` задаёт число результатов, `--json` даёт
машинный вывод. Ранжирование простое: точное совпадение, начало, вхождение. Пустая выдача — не
ошибка. Без `--agent` модель и сеть не нужны.

## Индекс кода

Индекс — кэш, а не знание: его можно удалить и построить заново, он не входит в git проекта.
Хранилище — SQLite с WAL и FTS5 (при отсутствии FTS5 — запасной поиск). Таблицы: файлы, извлечённые
записи, символы, связи, маршруты, таблицы и колонки, топики, конфигурация, строки, тесты, метки
требований, коммиты и секреты без значений.

Индекс не меняет статусы требований и не выдаёт вердиктов: он показывает, что видно в коде, с
координатами `файл:строка` и ревизией. Вердикты «выполнено по коду» появятся вместе с проверкой
критериев приёмки.

Для ассистента индекс доступен через MCP: `code_search` ищет по всем видам записей, `code_symbol`
находит символ, `code_file` читает диапазон строк клона. `code_file` работает только при
разрешении «Моделям» у репозитория и закрывает секретные имена и значения.

## Артефакты по коду: `TemplatesCode/` и `PromptCode/`

Какие документы можно собрать по коду, проект настраивает **папками**, а не сущностями в
`aurora.config.yaml`. Кит привозит преднастроенные виды, проект переопределяет нужные файлом с
тем же `kind`.

```text
TemplatesCode/cr-api_v1.0.md   паспорт вида и форма документа
PromptCode/cr-api.md           правила письма для этого вида
```

Паспорт шаблона: `kind`, `title`, `version`, `enabled`, `scope`, `out`, `prompt`, `purity`,
`order`. `enabled: "false"` выключает вид, не удаляя файл. `prompt` можно не указывать: по
умолчанию берётся `PromptCode/<kind>.md`. Проект переопределяет китовый вид файлом с тем же
`kind`; новый вид — новый файл с новым `kind`.

Преднастроенные виды:

| Вид | Что даёт | Включён |
|---|---|---|
| `cr-api` | спецификация HTTP API: маршруты, DTO, коды, валидация, авторизация | да |
| `cr-data` | схема данных: таблицы, колонки, ключи, связи, чтение/запись | да |
| `cr-events` | события и топики: издатель, потребитель, формат, гарантии | да |
| `cr-config` | конфигурация: ключ, значение, где читается, на что влияет | да |
| `cr-module` | карточка модуля: назначение, интерфейс, зависимости, тесты | да |
| `cr-algorithm` | алгоритм: вход, шаги, ветвления, ошибки, выход | да |
| `cr-rules` | бизнес-правила: условие, эффект, место, уверенность | да |
| `cr-crud` | матрица «обработчик × таблица» | да |
| `cr-tests` | карта тестов и пробелов | да |
| `cr-screen` | экранная форма: поля, действия, переходы | нет |
| `cr-mapping` | маппинг DTO ↔ сущность ↔ внешний формат | нет |
| `cr-sequence` | mermaid-последовательность от точки входа | нет |
| `cr-adr` | реконструкция решения, гипотеза | нет |

Формы опираются на OpenAPI, DbML, AsyncAPI, C4/arc42, 12-factor config и практику ADR. Общее
правило: каждое утверждение имеет ссылку `[cN]`, выдуманных имён и значений нет, раздел «Что не
удалось установить по коду» обязателен. Промпты задают эти правила текстом, их видно и можно
поправить.

```bash
python3 .aurora/scripts/code_artifacts.py --list
python3 .aurora/scripts/code_artifacts.py --check
python3 .aurora/scripts/code_artifacts.py --show cr-api
```

Настройки проекта для видов не нужны: правка шаблона или промпта в папке и есть настройка.

## Пакет требований истории: `code:pack`

Пакет собирает всё, что относится к номеру `US-1.1`: страницы Confluence, задачи Jira, артефакты
`Artifacts/us|ac` и карточки требований. Критерии приёмки разбираются из раздела «Критерии
приёмки» / «Acceptance criteria»: нумерованный список, пункты `- [ ]`, таблица «критерий — как
проверить» и Gherkin `Сценарий:`. У каждого критерия есть устойчивый id
`US-1.1/<группа>/<номер>#<хеш текста>`, токены (числа, даты, коды, версии) и черновые атомарные
части. Связанные артефакты помечены провенансом: `EXTRACTED` — связь из паспорта (`covers`,
`implements`, `ref_key`), `INFERRED` — только по упоминанию в тексте.

Пробелы называют то, чего не хватает для проверки: нет критериев, нет связанных артефактов, нет
алгоритма/контракта/маппинга, нет задачи Jira, критерий ссылается на артефакт, которого нет.
Пакет ничего не меняет и не вызывает модель.

```bash
python3 .aurora/scripts/code_pack.py --list
python3 .aurora/scripts/code_pack.py --story US-1.1
python3 .aurora/scripts/code_pack.py --story US-1.1 --json
python3 .aurora/scripts/code_pack.py --story US-1.1 --out Artifacts/requirements/US-1.1.md
```

## Необязательные адаптеры и граф: 1.203.1

`kb:code-graph` больше не обходит `Code/` ради таблиц, маршрутов и топиков: он берёт их из
индекса `code:index`, а `kb:graph-export` добавляет узлы маршрутов и топиков в
`meta/graphify/graph.json`. Без клонов и без индекса граф собирается как раньше, из SQL и
страниц зеркала.

Точный разбор можно подключить необязательными адаптерами. Пакеты в кит не входят и не
импортируются: слот включается командой в окружении, команда получает JSON
`{path,text,lang,role}` в stdin и отвечает JSON/JSONL записей схемы v1.

```bash
AURORA_CODE_GRAPHIFY='python3 /path/adapter.py' \
AURORA_CODE_TREESITTER='...' \
python3 .aurora/scripts/code_index.py --index --apply
```

Слоты: `graphify`, `tree-sitter`, `ast-grep`, `lizard`. Нет команды — слот молчит, индекс
строится на stdlib. Ошибка слота означает fallback на stdlib, а не падение файла.
`codeidx/measure.py` сравнивает время и число записей до включения адаптера.

## Проверка критериев по коду: `code:check`

`code:check --story US-1.1` берёт критерии из `code:pack` и ищет доказательства в индексе
кода: маршруты, таблицы, топики, символы, строки и тесты. У каждого критерия три вердикта:

- `найдено` — есть доказательства и все числа/коды критерия;
- `частично` — доказательства есть, но часть токенов не найдена;
- `не найдено` — в индексе нет ни одного факта.

Это не приговор и не вердикт «сделано». Доказательство — координата `файл:строка`; чего нет
в индексе, то не найдено, и это повод проверить код или расширить критерий. Модель и сеть не
нужны. `--json` даёт машинный отчёт, `--out` пишет Markdown.

```bash
python3 .aurora/scripts/code_check.py --story US-1.1
python3 .aurora/scripts/code_check.py --story US-1.1 --json
python3 .aurora/scripts/code_check.py --story US-1.1 --out Artifacts/checks/US-1.1.md
```

## Clean Room: `code:cleanroom`

`code:cleanroom --apply` собирает документы «как сделано» по каждому репозиторию и виду:
`CleanRoom/<вид>/<репозиторий>.md`. Факты берутся из индекса кода, у каждого утверждения
ссылка `[cN]` на `файл:строка`; раздел «Что не удалось установить по коду» обязателен.
Модель и сеть не нужны.

`CleanRoom/meta/passport.json` хранит ревизию репозитория, время индекса и список документов.
`--check` называет устаревшие и отсутствующие документы и возвращает 1, если пора пересобрать.

С `--agent` модель пишет только `cr-module`, `cr-algorithm` и `cr-rules`: она видит
пронумерованные факты индекса, обязана ссылаться на них `[cN]` и заполнить раздел «Что не
удалось установить по коду». Ответ без цитат, с выдуманной ссылкой или без раздела
отменяется, остаётся детерминированный документ с причиной. Модель зовётся только при
`code_repos.<repo>.models: true`, а модельный документ пишется только при
`code_repos.<repo>.publish: true`.

```bash
python3 .aurora/scripts/clean_room.py --apply
python3 .aurora/scripts/clean_room.py --agent --apply
python3 .aurora/scripts/clean_room.py --check
python3 .aurora/scripts/clean_room.py --json
```

Публикация остаётся через существующий `ship:publish` для выбранного документа: Clean Room
не пишет в Confluence сам. `ship:publish` проверяет `publish: true` у репозитория Clean Room
документа и без него отказывает.

## Здоровье индексов: `code:health`

`code:health` показывает по каждому репозиторию ревизию клона и индекса, свежесть, файлы,
маршруты, таблицы и топики. `--check` возвращает 1, если индекс отсутствует или отстал от
клона: это шаг cron-маршрута «Проверить свежесть индексов кода», а не ошибка панели.
Пересборка остаётся за `code:index --apply`; команда только читает.

```bash
python3 .aurora/scripts/code_health.py
python3 .aurora/scripts/code_health.py --check
python3 .aurora/scripts/code_health.py --json
```

## Раздел «Код»

Группа проекта, рядом с «Git». Карточка «Подключить репозиторий» — строка `git clone`, название
папки, вход и два переключателя («Моделям», «Публиковать»); «Проверить и подключить» сначала
спрашивает сервер (`ls-remote` тем же входом), затем записывает реестр. У каждого репозитория —
состояние клона, ревизия, отставание, последняя синхронизация, языки и размер; «Синхронизировать»,
«Сбросить клон» (при правках или чужом адресе), «Настроить» (адрес, провайдер, ветка, ревизия,
маски, связь, разрешения, вход, «Проверить подключение») и «Убрать из списка» — клон при этом
остаётся на диске: удалять данные движок не берётся. Синхронизация идёт заданием панели и видна в
«Консоли». Ночью — шаг маршрута «Обновить базу» или команда `code:sync --apply` в разделе «Cron».
Маски не обязательно печатать: когда клон есть, «Выбрать…» у поля открывает папки клона, и отмеченные
папки дописываются масками `папка/**`; ключ SSH выбирается в окне из `~/.ssh`.

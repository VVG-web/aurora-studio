# Команды Aurora Studio

Справочник собран автоматически (`kit:list`) для версии движка **1.193.0**.
Модификаторы взяты из `--help` самих скриптов, поэтому не расходятся с кодом;
остальное — из реестра `commands.txt`. Править руками этот файл бессмысленно:
он перезаписывается командой `python3 .aurora/scripts/kit_commands.py --md`.

Короткие имена в скобках — исторические алиасы, работают всегда.
«Исполнитель» показывает, где проходит граница: **скрипт** — детерминированная
механика, её результат воспроизводим; **модель** — работа со смыслом;
**скрипт+модель** — скрипт считает и готовит, решение принимает человек.

## Коды возврата и ворота качества

Команда сообщает итог кодом выхода — один для всех скриптов и шагов маршрута:

| Код | Смысл |
|---|---|
| `0` | ок: замечаний нет |
| `1` | замечания: команда отработала и нашла, что чинить; у шага-ворот это «ворота не пройдены» |
| `2` | сбой выполнения: команда не смогла отработать (плохие аргументы, нет данных, отказ) |
| `3` | необработанная ошибка скрипта (трассировка — в выводе); как сбой |
| другой код `2` и выше, меньше нуля | сбой; отрицательный — процесс прерван |

Обычный шаг маршрута с кодом `1` маршрут не останавливает: это нормальное состояние живой базы, итог перечислит такие шаги как «нашла, что чинить». Остановка — код `2` и выше.

**Ворота.** Шаг, у которого в `cockpit/scenarios.txt` среди флагов стоит `--gate`, считается воротами качества: код `1` на нём останавливает маршрут (причина `gated`, `failed=<команда>`, в журнале «Маршрут остановлен на воротах»). Шаг не попадает в список пройденных, и «Продолжить маршрут» повторит ворота после правки. Итог прогона не считает такую остановку сбоем выполнения. Флаг `--gate` передаётся самому скрипту: скрипт без ворот-режима его не знает, поэтому `--gate` ставится только у шагов, чьи скрипты его поддерживают. Вывод ворот не должен содержать признаков обрыва сети («timeout», «ssl», «connection error» и т. п.): код `1` с ними маршрут принимает за сетевой сбой и ждёт, а не за вердикт (если ворота не назвали вердикт машинной строкой, см. ниже). В `aurora.py route` остановка на воротах — выход `1` (остановлен), а не `2` (сбой выполнения).

**Строка вердикта.** Скрипт-ворота может, кроме кода выхода, напечатать машинную строку `AURORA-GATE {"gate": "<имя>", "verdict": "pass|warn|fail", "items": [{"id": "…", "detail": "…"}], "waivable": false}` (`run_summary.emit_gate`). Консоль её не показывает, а нарушенные пункты (`id` и `detail`) маршрут выводит в журнал списком, и вердикт ложится в запись шага. Правила шага-ворот: код `1` — не пройдены; код `0` при вердикте `fail` — тоже не пройдены (расхождение читается как fail-closed, неизвестный вердикт — это `fail`); `warn` при коде `0` — маршрут идёт дальше с предупреждением в журнале (режим внедрения); код `0` без строки — ок: скрипты прошлых выпусков и скрипты без адаптера не ломаются, строка — деталь, а не вердикт. Шаг, назвавший вердикт строкой, за сетевой сбой не принимается. У шага без `--gate` вердикт только записывается и показывается.

**Скрипты с режимом ворот.** `spec_pack.py` (`make:spec-pack`): с `--gate` риски передачи Definition of Ready (требования не в `agreed`, открытые вопросы, основания ниже `verified`, отсутствующие основания) дают код `1` и строку `AURORA-GATE` (ворота `spec_pack`, у каждого риска `id` и `detail`), без рисков — код `0` и `pass`; ошибка входа (нет базы, нет спеки) в этом режиме — код `2`. Без `--gate` скрипт ведёт себя как прежде: риски печатаются, код `0`. Остальные скрипты с флагом: `kb_trace.py --requirements --gate` (`ops:trace`) — разрывы цепочки пункт ТЗ → требование → эпик/история → приёмка (раздел «Разрывы» таблицы, у каждого `id` и `detail`) дают код `1`, цепь цела — `0` и `pass`; `kb_lint.py --gate` (`kb:lint`) и `artifact_lint.py --gate` — те же ошибки и замечания, что скрипты и так находили, становятся пунктами вердикта (у `kb_lint` пункт назван видом ошибки — `broken-link`, `orphan-card`…; в строку вердикта идут первые 50 пунктов, полное число — в поле `total`), а их коды прежние (`0` — чисто, `1` — есть). Нет базы в режиме ворот — код `2` у всех четырёх скриптов (у `artifact_lint` «нет базы» — нет ни одной папки артефактов: проект с `Artifacts/us` проверяется и без `AuroraKnowledgeDB/`); ещё `2` у `kb_lint`, когда база — ссылка за пределы проекта (карточки не проверены, а не «чисто»), и у `artifact_lint` с файлами без `--profile`. **Режим внедрения** (у всех четырёх): `--gate=warn` (или переменная окружения `AURORA_GATE_MODE=warn`) печатает вердикт `warn` и возвращает `0` — для маршрута проекта с историческими красными проверками; шаг с `--gate=warn` воротами не считается и маршрут не останавливает, предупреждение попадает в журнал. Без `--gate` строки вердикта нет и коды прежние. **Ревью** `review_run.py --page … --gate` (`make:review-auto`, одна страница): порог оценки (9,0) становится кодом выхода — «готова к передаче» без замечаний даёт `pass` и `0`, с оговорками (не пройдены или не определены мелкие вопросы, ответы неустойчивы) — `warn` и `0`, оценка ниже порога или критичные и важные замечания — `fail` и `1`. Первый пункт вердикта `score` несёт баллы, дальше идут не пройденные и не определённые вопросы чек-листа (`id` вопроса и текст). Сбой самого прогона (нет доступа к Confluence, страница не прочитана, нет годного прогона модели, не хватает покрытия, обрыв обращения) — код `2` без вердикта, раньше это был код `1`. Пакет с `--gate` — ошибка вызова. Без `--gate` коды прежние: в тексте `0`, у `--json` — по статусу.

## Развёртывание (из клона kit'а, не из проекта)

| Команда | Что делает |
|---|---|
| `python3 aurora.py new <target>` | развернуть Aurora в проект: скелет, движок, интерактивная настройка |
| `python3 aurora.py setup <target>` | перенастроить проект (Confluence, Jira, приватность, пороги) |
| `python3 aurora.py update <target>` | обновить движок до версии kit; `--apply` пишет, `--structure-only` — только папки |

Любую команду обслуживания можно звать и из kit'а: `python3 aurora.py <команда> <target> [флаги]`.

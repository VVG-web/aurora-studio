# Aurora Control Panel — требования к HTML-интерфейсу

Единая локальная панель управления фреймворком Aurora: **справка → команды → здоровье базы →
доустановка компонентов → обновление kit/миграция → все проекты на машине** в одном окне.
Оформление — по палитре комикса «AURORA VAULT» (тёмный командный «Волт»), статусы наследуют
цвета trust-уровней карточек, ошибки — цвет злодея Энтропии.

---

## 1. Назначение и принципы

- **Одно окно.** Все задачи (справка, запуск команд, отчёты, установка, миграция, обзор
  проектов) — внутри одного SPA; переход к проекту — маршрутизация, не новое окно.
- **CLI — источник правды.** UI ничего не считает сам: он вызывает `aurora.py <cmd>` и
  рендерит вывод (предпочитая `--json`, где есть). Логика остаётся в ките.
- **Read-only по умолчанию, действия — по подтверждению.** Наблюдение безопасно; всё, что
  меняет файлы/публикует, — за явным подтверждением (см. §3).
- **Никаких секретов в UI.** Токены/пароли не вводятся и не показываются; MCP-авторизация
  остаётся в Cursor. Панель лишь показывает статус «настроено / нет».
- **Наследование от комикса.** Визуальный язык, цвета статусов и мотивы — продолжение
  комикса-онбординга, чтобы новичок узнавал те же «шарды» и уровни доверия.

## 2. Функциональные модули

### 2.1 Reference / Справка
- **Источник правды по командам — реестр `commands.txt`** (48 команд): неймспейс, алиасы,
  исполнитель (скрипт / модель / скрипт+модель), реализация, версия появления, описание.
  Модификаторы панель берёт не из текста, а из `--help` самих скриптов — так же, как это
  делает `kit:list` (`kit_commands.py`). Разбор markdown-таблиц `SKILL.md` не нужен.
- Рендер `SKILL.md`, `references/*.md`, `docs/*`, легенда trust-уровней и семантика папок
  (Sources/Raw/AuroraKnowledgeDB/Artifacts/Deliverables/Workspaces).
- Полнотекстовый поиск по справке и по реестру; оглавление; deep-link на команду.
- У каждой команды: описание, аргументы, модификаторы, чем исполняется, с какой версии
  доступна, и кнопка **«Выполнить»** → Console (§2.2) с подставленной командой.
  Команды с исполнителем «модель» кнопки запуска не имеют: их выполняет ассистент по
  процедуре из `references/`, панель показывает саму процедуру.

### 2.2 Command Runner / Консоль
- Запускает `python3 aurora.py <cmd> <target> [flags]` через локальный раннер (§3).
- **Палитра команд** со всеми глаголами `aurora.py`; выбор целевого проекта (из §2.6).
- **Класс команды определяет поведение.** В движке действует единое правило: скрипт,
  который пишет, по умолчанию делает dry-run, а запись включает `--apply`. Панель опирается
  на это, а не на свой список:
  - *наблюдение* — команда без `--apply` в аргументах (`doctor`, `stats`, `lint`, `queue`,
    `impact`, `context`, `audit`, `diff`, `classify`, `trace`, `scrub`, `list`, `build-plan`,
    `spec-pack`, `jira-status`, `update` без `--apply`) — запускается свободно;
  - *запись* — присутствует `--apply` (`fix`, `retire`, `verify`, `supersede`, `index`,
    `release`, `update`, `jira-status --link`) — требует подтверждения, а перед ним
    показывается тот же прогон без `--apply`;
  - *наружу* — `publish`, `sync-confluence`, `sync-jira`, `export`: нужен доступ к сети и
    токен, публикация меняет чужую систему → двойное подтверждение;
  - *развёртывание* — `new`, `setup`: только из kit, с явным указанием пути.
- Потоковый вывод stdout/stderr; если команда отдаёт `--json` — структурированный рендер,
  иначе моно-лог. Код возврата подсвечивается (0 — teal, >0 — Entropy-red).
- История запусков на проект.

### 2.3 Health Dashboard / Здоровье базы
Источник: `stats <target> --json` — единственная команда движка с машинным выводом; ключи
фиксированы: `total`, `trusted`, `pct_verified`, `bootstrap`, `statuses`, `sections`,
`expired_count`, `no_owner_count`, `orphans_count`, `missing_source_count`, `req_total`,
`req_status`, `req_agreed_no_jira`, `decisions`, `specs`, `questions_open`,
`questions_overdue_count`, `blocked_objects`, `acceptance`, `req_implemented_no_acceptance`,
`artifacts_total`, `artifacts_with_based_on`, `risky_deliverables`. Остальное — текстовый
вывод `lint`, `doctor`, `audit`, `classify` с разбором ключевых строк.
- Плитки: всего карточек; **разбивка по статусам** полосой в цветах trust-уровней;
  **% verified** кольцевым индикатором (+флаг bootstrap-режима при значении ниже порога
  `bootstrap.verified_threshold_pct` из конфига); протухшие `review_by`; карточки без
  владельца; сироты; битые источники; битые ссылки и дубли (из `lint`); **drift** (из
  `diff`); покрытие требований (REQ → SPEC → Jira → приёмка, из `trace`); открытые и
  просроченные вопросы; DR и спеки; доля артефактов с `based_on`; риски поставки.
- **Очередь верификации** (`queue`) — карточки, ранжированные по ценности.
- Тренд из `meta/metrics.md` (спарклайны).
- Любая метрика кликабельна → дрилл к списку проблемных карточек или к команде-починке
  (`fix`, `verify`, `supersede`).

### 2.4 Install / Setup Advisor / Что доустановить
Источник: `doctor` (+ проба окружения самой панелью).
- Чек-лист компонентов с состоянием (ok / warn / missing) и тем, **что каждый включает**:
  - Python 3.9+, git — базовые;
  - `aurora-vault` skill и sync-скиллы в `.opencode/skills/`, полный набор скриптов движка;
  - **доступы для синка** — есть ли `.env.aurora.local` и заполнены ли в нём
    `CONFLUENCE_PERSONAL_TOKEN` / `JIRA_PERSONAL_TOKEN`. **Показывается только факт
    «заполнено/пусто», значение не читается и не рендерится никогда**;
  - **Atlassian MCP** — настроен ли в Cursor (только факт, без секретов);
  - pandoc — нужен `ship:export`; `bs4`, `markdownify`, `lxml` — `sync:confluence`;
    `markitdown`/`pypdf`/`openpyxl` — `kb:ingest-office`. Каждая строка называет, какие
    команды без неё не работают;
  - `aurora.config.yaml` (полнота: `project.name/slug`, `confluence.space`,
    `jira.project_key`, `privacy.scrub`), версия движка проставлена, структура папок
    совпадает со схемой, git-хук линтера установлен, базовая линия храповика
    (`meta/lint_baseline.txt`) не отстала от факта.
- У каждой строки — **действие**: «Установить skill», «Скопировать конфиг из kit», «Создать
  недостающие папки» (`update --structure-only --apply`), «Поставить git-хук линтера» (`hooks`),
  «Настроить проект» (`setup`). Действия — из §2.2 (с подтверждением).

### 2.5 Kit Version & Migration / Версия и миграция
- Показ версии kit (`VERSION`) против версии движка проекта (`aurora_version.txt`); бейдж
  «актуально / отстаёт на N».
- Просмотр `CHANGELOG.md`.
- **«Предпросмотр обновления»** → `update <target>` (dry-run): список файлов движка, которые
  изменятся (в пределах `engine_manifest.txt`), и `*.new` рядом с пользовательскими шаблонами.
- **«Применить»** (подтверждение, «золотой» акцент) → `update --apply`, затем напоминание
  сделать git-commit. Предупреждение про **симлинк-движок** (обновление затронет общую цель).
- Показ `.opencode/update_ignore.txt` — что проект сознательно ведёт по-своему, и списка
  `*.new`, оставленных прошлым обновлением рядом с локализованными шаблонами.
- Миграция чужого проекта на схему: `update --structure-only --apply` создаёт недостающие
  папки, дальше разбор off-schema папок по слоям — процедура в `references/migration.md`.

### 2.5а Setup / Настройка и подключение проекта
- **Подключить новый проект** формой: путь, название, slug, пространство Confluence, ключ
  Jira → `install_aurora.py`. Путь разрешён **только внутри корней поиска панели**:
  произвольное место на диске из браузера не создаётся.
- **Правка `aurora.config.yaml` текстом.** Список корней синка проще дописать строкой, чем
  прокликать формой; перед записью прежняя версия сохраняется рядом как `.bak`.
- **Несохранённое видно и не теряется молча.** Правка в любом блоке окрашивает его
  кнопку сохранения в «золото» (тот же код, что у необратимых действий) и добавляет метку
  «не сохранено». Уход из раздела и закрытие вкладки спрашивают подтверждение, **называя
  блоки поимённо** — человек должен знать, что именно потеряет.
- **Токены синка** — два поля типа password. Значение уходит на запись и **никогда не
  возвращается в браузер**: панель знает только «заполнено / пусто». Файл
  `.env.aurora.local` пишется с правами 600.

### 2.4б Выбранный проект в шапке
Половина разделов работает не «вообще», а с одним конкретным проектом, и на этих экранах
Мостика не видно. Поэтому в шапке всегда висит либо имя выбранного проекта с точкой цвета
его ауры, либо «Проект не выбран» пунктиром. Нажатие ведёт на Мостик — сменить проект.

### 2.5б Quick start / Быстрый старт
Рутина по сценариям, а не по алфавиту: «утренний обход», «пополнить базу», «верификация»,
«прополка», «требования и разработка», «наружу». Сценарии объявлены в
`cockpit/scenarios.txt` — обычный текст, который правит человек. Шаг без команды — работа
человека или ассистента: панель её не запускает, но и не прячет.

### 2.5в About / О проекте
Версия kit и панели, репозиторий, ветка, коммит, автор, лицензия, последние выпуски.
Здесь же **обновление kit из репозитория кнопкой**: сначала проверка (что приедет,
насколько отстали, нет ли своих незакоммиченных правок), потом перемотка вперёд.
Слияние с расхождением кнопкой не делается. После обновления панель просит перезапуска —
сервер работает со старого кода.

### 2.6 Projects Overview / Все проекты на машине
- Обнаружение проектов: скан заданных корней на `aurora.config.yaml` + `aurora_version.txt`.
- Сетка плиток-«башен»: имя/slug, версия движка (+бейдж «отстаёт»), сводка здоровья
  (% verified, число проблем по тяжести), последний sync/diff, drift.
- **Цветовая аура плитки** по тяжести: teal — здоров, amber — предупреждения, Entropy-red —
  блокеры.
- Клик по плитке → дрилл в дашборд/консоль этого проекта **в том же окне** (роутинг).
- Глобальная сводка проблем по всем проектам сверху.

## 3. Данные, архитектура, безопасность

- **Тонкий локальный раннер — `cockpit/aurora_cockpit.py`**: HTTP на `127.0.0.1`, только
  стандартная библиотека Python (контур закрытый, ставить нечего). Эндпоинты оборачивают
  `python3 aurora.py <cmd> <target> [флаги]` и возвращают JSON или поток stdout.
  Панель — один self-contained HTML (инлайн CSS/JS, без CDN), раздаётся тем же раннером.
- Где команда умеет `--json` (`stats`) — UI берёт его; остальное текст с разбором ключевых
  строк (`doctor`: `ERROR:` / `WARN:` / `OK:`; `lint`: «ошибок N»; `audit`: MISSING/ORPHAN).
- **Безопасность.** Раннер слушает только петлевой интерфейс и требует токен сессии,
  выданный при старте (случайный, живёт в памяти процесса). Запускать можно **только
  команды из реестра `commands.txt`** — произвольная строка не исполняется, аргументы
  передаются списком, без оболочки. Целевой проект выбирается из списка обнаруженных, а не
  вводится руками. Флаг `--apply` панель добавляет сама и только после подтверждения.
  Секреты не принимаются формой и не выводятся: панель знает лишь «заполнено / пусто».
- **Оффлайн:** UI работает без интернета; сетевые только `sync:*` и `ship:publish` — их
  статус честно показывается как «нужен токен и сеть», а при отсутствии токена кнопка
  запуска неактивна с объяснением, а не с молчаливой ошибкой.
- **Скины.** Оформление вынесено из разметки в `cockpit/skins/*.css`: панель задаёт
  структуру, скин — цвета, шрифты, радиусы. Файл появляется в списке сам, имя и описание
  берутся из его шапки. Пользовательский скин добавляется копированием файла, без правки
  сервера и интерфейса. Тема (светлая/тёмная) работает поверх скина.
- **Тех-конвенция темизации** — CSS-custom-properties + перекрытие
  `:root[data-theme="light|dark"]`; запасной набор токенов остаётся в разметке, чтобы
  панель читалась даже если скин не загрузился.

## 4. Требования к оформлению (визуал) — палитра комикса

### 4.1 Идентичность
«**AURORA VAULT — командная башня**»: тёмный, кинематографичный, супергеройско-технический
язык, продолжающий комикс. Не ботанический (старые гайды) — а midnight-navy «Волт» со
свечением. Тёмная тема — основная; светлая — доступная альтернатива.

### 4.2 Цветовые токены (dark — основная / light — альтернатива)

| Токен | Роль | Dark | Light |
|---|---|---|---|
| `--bg` | фон «Волта» | `#0A0F1E` | `#F5F7FC` |
| `--surface-1` | панель | `#111A30` | `#FFFFFF` |
| `--surface-2` | приподнятое | `#17223D` | `#EEF2FA` |
| `--border` | линии | `#263353` | `#D3DBEA` |
| `--text` | основной текст | `#EAF0FA` | `#131A2B` |
| `--text-muted` | вторичный | `#93A0BC` | `#5A6683` |
| `--primary` (аврора-бирюза) | первичное действие, «здорово» | `#2EE6C8` | `#0FB89E` |
| `--accent` (магента) | акцент, присутствие Авроры, выбор | `#FF4DA3` | `#D42C82` |
| `--gold` (золото) | эталон/«released», премиум-акцент | `#F7C948` | `#C79A16` |

### 4.3 Trust-уровни = семантика статусов (ключевая идея)
Те же цвета, что у шардов в комиксе, — это **и** статусы карточек базы, **и** состояния UI.
Один визуальный код от комикса до данных:

| Статус карточки | Токен | Dark | Смысл в UI |
|---|---|---|---|
| imported | `--tier-imported` | `#8592A8` (серый) | нейтральное/непроверенное |
| draft | `--tier-draft` | `#9DC0FF` (бело-голубой) | черновик/гипотеза |
| in-review | `--tier-inreview` | `#FFA62B` (янтарь) | внимание/в работе → **warn** |
| verified | `--tier-verified` | `#2EE6C8` (бирюза) | ок/подтверждено → **success** |
| deprecated | `--tier-deprecated` | `#6E63C9` (индиго) | архив/история |

### 4.4 Danger / «Энтропия»
Проблемы, что ловит health-чек (drift, битые ссылки, протухшее, секреты в git, блокеры doctor),
красятся «цветом врага»:

| Токен | Роль | Dark |
|---|---|---|
| `--danger` (Энтропия-red) | ошибка/блокер/провал команды | `#FF4D5E` |
| `--corruption` (violet-static) | «порча»: drift, рассинхрон зеркал | `#B24BFF` |

### 4.5 Типографика
- **Заголовки** — плотный геройский гротеск (напр. Inter/Manrope, вес 700–800), допускается
  лёгкий «леттеринг» в шапке модуля.
- **Текст** — системный sans (`-apple-system, Segoe UI, Roboto…`), line-height 1.5.
- **Числа метрик и команды/логи** — моноширинный (`ui-monospace, Consolas`); команды
  `/aurora-vault …` и CLI — в «терминальных» плашках (тёмный фон, teal-текст).

### 4.6 Мотивы и компоненты
- **Shard-chip (статус-чип)** — базовый элемент: гранёный шард в цвете trust-уровня + **иконка/форма**
  (цвет не единственный признак) + опц. «сигила владельца» и «кольцо-таймер» для `review_by` (прямая
  цитата из комикса). Используется в списках карточек, очереди верификации, дриллах.
- **Tesseract-линии / гиперкуб** — мотив Авроры: лоадеры, разделители секций, пустые состояния
  («база чиста»), фон шапки. Тонко, без перегруза.
- **Свечение/rim-light** — на активных/hover-элементах и на первичных кнопках (teal-glow);
  «золотое» свечение — на подтверждении необратимых действий.
- **Кольцевые индикаторы** (% verified+, покрытие) — «энергетические» кольца в teal→gold.
- **Console** — терминал teal-на-navy, halftone-текстура фоном (очень слабо).
- **Project-tile** — «башня» с цветной аурой здоровья; бейдж версии; мини-кольцо verified.
- **Health-плитки** — крупное число (моно) + подпись + микро-тренд; клик = дрилл.

### 4.7 Состояния и обратная связь
- Обяз. состояния для всех интерактивных: hover, active, **focus-visible** (заметное teal-кольцо),
  disabled, loading (tesseract-спиннер), empty, error.
- Запуск команды: «энергозаряд»/кольцо прогресса; успех — teal-вспышка + галочка; ошибка —
  Entropy-red рамка + текст stderr.
- Тосты: success=teal, warn=amber, error=red, info=magenta.

### 4.8 Движение
- Короткие, «энергетические» переходы (150–250 мс), свечение на действии, кольца-таймеры.
- Обязательно уважать `prefers-reduced-motion`: отключать глоу-пульсацию и анимации колец.

### 4.9 Доступность
- Контраст текста ≥ WCAG **AA** в обеих темах (проверить teal/gold/amber на тексте — для мелкого
  использовать затемнённые варианты, яркие — только для крупного/графики).
- **Цвет — не единственный сигнал**: каждый trust-уровень и danger сопровождать иконкой/подписью
  (критично — уровни различаются цветом).
- Полная клавиатурная навигация; командная палитра по `⌘/Ctrl-K`; ARIA-роли для метрик и таблиц.

### 4.10 Do / Don't
- **Do:** тёмный «Волт» как база; teal = здорово/первично; gold = эталон/подтверждение
  необратимого; red/violet = проблемы; один код статусов от комикса до данных.
- **Don't:** не использовать старую ботаническую (sage/green) палитру; не красить обычные
  нейтральные элементы в red/gold; не полагаться на цвет без иконки; не прятать секреты-поля в UI.

---

## 5. Нефункциональные требования
- **Single-window** SPA, разделы/табы, роутинг между проектами без нового окна.
- **Self-contained** ассеты (инлайн CSS/JS), запуск локально без CDN.
- **Оффлайн-first**; сетевые только явные sync-действия.
- **Отзывчивость**: 320px → десктоп; таблицы/логи со своим горизонтальным скроллом.
- **Производительность**: дашборд из `stats --json` открывается < 1 c на среднем проекте;
  тяжёлые команды — асинхронно, с прогрессом.
- **Темизация** через CSS-переменные + `prefers-color-scheme` + `data-theme`.

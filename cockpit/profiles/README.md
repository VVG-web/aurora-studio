# Профили рабочего места

Профиль — набор того, что человек видит в панели: какие **сценарии** и **разделы** показаны. Роль («аналитик», «разработчик», «тестировщик») — это не права доступа:
профиль только прячет лишнее, а скрытое остаётся рабочим (расписание Cron и запуск маршрута
из терминала профилем не ограничиваются; кнопки панели запускают скрытый маршрут по его id — для этого `/api/scenarios?all=1` отдаёт все маршруты, скрытые с `hidden: true`). Новая роль добавляется файлом, ядро править не нужно.

## Фиче-флаг «роли для профилей»

Всё, что описано ниже про выбор и действие ролей, работает **только при включённом флаге `profiles`**.
По умолчанию он **выключен**, и панель ведёт себя ровно как до ролей: активный профиль всегда «all»,
`local/profile.json` не читается и не пишется, строки «Role» в «Настройке» нет, разделы и сценарии не
скрыты, `GET /api/profiles` отдаёт только «all» и `enabled: false`, `POST /api/profile/choose` отвечает отказом.

* **Где включить.** Раздел **«Разработка»** (виден после семи нажатий на «О проекте»): карточка «Роли для профилей»,
  кнопка «Включить»/«Выключить». Страница после переключения перечитывается.
* **Где хранится.** `local/features.json` кита: `{"profiles": true}`. Папка `local/` закрыта `.gitignore`
  и обновлением кита не трогается — флаг живёт на машине владельца, в git проекта не попадает.
  Путь можно переопределить переменной `AURORA_FEATURES_FILE` (так прогон тестов не видит флаги владельца).
* **Что даёт.** В «Настройке» появляется строка **«Role»**: выбор пишет `local/profile.json`, меню и маршруты
  пересобираются под роль. Выключили флаг — выбор остаётся в `local/profile.json`, но не читается; включили
  снова — роль вернётся.

## Роли кита

Шесть ролей, как в стандартной команде. Названия — **английские в обоих языках** (`name` — строка), описания
переведены. Состав — по фактическим разделам (`cockpit/modules/*/module.json`) и маршрутам
(`cockpit/scenarios.txt`: `update` обновить, `fix` починить, `rebuild` пересобрать, `write` написать артефакт,
`deliver` сдать документы). Мостик, «Настройка», «Проект», «Файлы» и «Консоль» встроены в ядро и видны всем ролям.

| Роль (`id`) | Разделы (`modules`) | Маршруты (`scenarios`) | Зачем |
|---|---|---|---|
| **Analyst** (`analyst`) | health, quickstart, work, ask, mirrors, reference | update, fix, write | требования и знание: состояние базы, источники, артефакты, «Спросить» |
| **Developer** (`developer`) | gitsync, graph, commands, ask, quickstart, version, install, reference | update, fix | репозиторий и движок: Git, команды, связи карточек, версия кита, установка |
| **Tester** (`tester`) | health, quickstart, reports, ask, mirrors, commands, reference | fix | проверка: метрики и находки базы, отчёты, зеркала источников, команды проверок |
| **Product Owner** (`product-owner`) | health, quickstart, work, ask, reports, reference | write, deliver | продукт: требования, артефакты и их выдача, отчёты |
| **Project Manager** (`project-manager`) | health, quickstart, work, cron, reports, mirrors, ask, reference | update, deliver | ход проекта: здоровье базы, продуктивность, расписание, отчёты |
| **Team Lead** (`team-lead`) | всё из Developer и Project Manager плюс bots и models | все (поля нет) | руководитель видит всё рабочее и настройки машины: боты, модели, Cron, Git |

Тестировщику отдельных маршрутов проверки в ките нет: ему достаётся `fix` (проверка и ремонт базы) и
разделы метрик; когда такие маршруты появятся, их `id` дописывают в пресет. Разделы `graph` и `reports` помечены
`dev: true` и показаны, только пока открыты «Разработка» — как и без ролей.

**Что роль скрыть не может.** Мостик и «Настройка» встроены в ядро; «Разработка» (`dev`) и «О проекте» (`about`)
сервер никогда не помечает `hidden`, даже если их нет в `modules` (`PROFILE_KEEPS`): в «Разработке» выключатель ролей,
а «О проекте» её открывает — иначе человек не вернул бы профиль «all». Поэтому меню пустым не бывает.

**Известная граница.** Роль не ограничивает Cron (расписание ведёт любые маршруты и команды) и запуск маршрута из
терминала (`aurora.py ...`). Это видимость панели, а не права; ограничивать запуск профилем решено не было.

Профиль **«all»** («всё») задан кодом и файла не требует: все сценарии и разделы кита, поведение
без профиля. Им становится выключенный флаг и любой неясный выбор: нет `local/profile.json`, в нём нет `id`,
пресета с таким `id` нет или он не принят. Файл `all.json` имя «all» не перебивает.

## Пресет роли

Файл `cockpit/profiles/<id>.json`; `id` совпадает с именем файла (без `.json`):

```json
{
  "id": "analyst",
  "name": { "ru": "Аналитик", "en": "Analyst" },
  "about": { "ru": "Работа с требованиями и базой.", "en": "Requirements and the knowledge base." },
  "scenarios": ["fix", "update"],
  "modules": ["work", "ask", "graph"]
}
```

| Поле | Что значит |
|---|---|
| `id` | имя файла без `.json`; расходится — пресет не принят, причина в ответе `/api/profiles` |
| `name` | название на каждом языке; обязательно |
| `about` | пояснение на каждом языке |
| `scenarios` | список `id` сценариев из `cockpit/scenarios.txt`, которые видны; нет поля — видны все; порядок остаётся порядком файла сценариев |
| `modules` | список `id` разделов панели, которые видны; нет поля — видны все (панель прячет остальные разделы: без кнопки меню и без монтирования; это видимость, а не права); `dev` и `about` скрыть нельзя |
| `api_version` | необязательно; нет — это `1`; новее, чем знает движок, — пресет пропущен |

**Проверка.** Файл читает общий загрузчик манифестов (`aurora_common.load_manifest`, вид
`profile`, режим «мягкий»). Не JSON, нет `id` или `name`, `id` не совпал с файлом, `api_version`
из будущего — пресета нет, причина лежит в `warn` ответа `/api/profiles`. Необязательное поле не
того типа — пресет поднимается без него (то есть «видно всё»), с предупреждением. В списках
`scenarios` и `modules` берутся только непустые строки; `id`, которого нет среди маршрутов `scenarios.txt` или папок `cockpit/modules`, — предупреждение в `warn` (молчать об опечатке, которая прячет нужное, нельзя); лишнее отбрасывается с предупреждением. Если годных строк не осталось вовсе (`[7]`, `[""]`), поле считается неверным: оно не применяется («видно всё»), с предупреждением. Явный пустой список `[]` — не ошибка, он прячет всё, кроме `dev` и `about`. Пустое `name` — пресет не принят.

## Выбор на машине

Выбор (при включённом флаге) делает строка «Role» в «Настройке» и пишет `local/profile.json` кита: `{"id": "analyst"}`. Папка `local/` закрыта
`.gitignore` и обновлением кита не трогается, поэтому выбор переживает обновление.
Путь можно переопределить переменной окружения `AURORA_PROFILE_FILE` (так прогон тестов не видит выбор владельца).
`GET /api/profiles` отдаёт `{profiles: [{id, name, about}], active, warn, enabled}`.

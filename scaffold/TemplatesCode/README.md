# Шаблоны артефактов по коду (`TemplatesCode/`)

Формы документов, которые движок собирает по коду: API, данные, события, конфигурация, модули, алгоритмы, правила, CRUD и тесты. Шаблон задаёт разделы, порядок и поля; правило «каждое утверждение со ссылкой `[cN]`» общее для всех.

- **Что класть:** Один файл на вид, `<вид>.md` (например, `cr-api.md`). Вид выбирается в `TemplatesCode/`, правила письма — в `PromptCode/`.
- **Чего не класть:** Готовые документы проекта (они в `Artifacts/` или `CleanRoom/`), промпты (они в `PromptCode/`), формы артефактов аналитика (они в `TemplatesCommon/`).
- **Кто пишет:** Человек и кит (преднастроенные виды поставляются с китом).
- **Вложенные папки:** Не заводите: движок ищет шаблоны только в самой папке.

# TemplatesCode: виды артефактов по коду

Каждый файл в этой папке описывает **один вид артефакта, который можно собрать по коду**.
Паспорт в шапке говорит движку, что это за вид, по какому шаблону строить, каким промптом
писать и в какую папку класть результат.

```yaml
---
kind: cr-api
title: "Спецификация API по коду"
version: "1.0"
enabled: "true"
scope: route
out: Artifacts/contracts/code
prompt: PromptCode/cr-api.md
purity: traceable
order: 10
---
```

Поля:

| Поле | Что значит |
|---|---|
| `kind` | идентификатор вида; по нему движок отличает виды и находит переопределения |
| `title` | название для человека |
| `version` | версия шаблона; растёт при правке формы |
| `enabled` | `"true"` или `"false"`; выключенный вид не предлагается и не генерируется |
| `scope` | что именно описываем: `symbol`, `route`, `controller`, `module`, `table`, `topic`, `pair`, `component`, `service` |
| `out` | папка результата относительно корня проекта |
| `prompt` | путь к промпту; пусто — `PromptCode/<kind>.md` |
| `purity` | `traceable` (по умолчанию) или `strict` |
| `order` | порядок в списке и в панели |

## Как это работает

1. Кит привозит **преднастроенные** файлы в `TemplatesCode/` и `PromptCode/`. Новый проект
   получает их сразу и может генерировать документы по коду без настройки.
2. Проект может **переопределить** любой вид: положить свой файл с тем же `kind` в
   `TemplatesCode/`. Он заменит китовый, остальные останутся.
3. Можно **добавить** свой вид: новый файл с новым `kind`, своим шаблоном и промптом.
4. Можно **выключить** вид: `enabled: "false"`. Файл остаётся, вид не предлагается.
5. `aurora.config.yaml` для этого не нужен. Настройка живёт в папках, её видно в git и
   можно отревьюить как обычный текст.

## Правила шаблона

- `{{ПЛЕЙСХОЛДЕРЫ}}` заменяет движок; в готовом документе их быть не должно.
- Комментарии `<!-- ИНСТРУКЦИЯ: ... -->` обязательны для модели и человека.
- Каждый факт в тексте имеет ссылку `[cN]`; ссылки расшифровываются под границей чистовика.
- Раздел «Что не удалось установить по коду» обязателен. Пустой — значит, всё видно.
- Никаких выдуманных имён, чисел, статусов и кодов. Только то, что есть во фрагментах.
- `purity: strict` убирает из тела имена и ссылки, оставляя функциональные факты.

## Проверка

```bash
python3 .aurora/scripts/code_artifacts.py --list
python3 .aurora/scripts/code_artifacts.py --check
python3 .aurora/scripts/code_artifacts.py --json
```

`--check` называет шаблон без файла, промпт без файла, негодную папку результата, неизвестный
`scope` или `purity`. Молча пропущенного вида не бывает.

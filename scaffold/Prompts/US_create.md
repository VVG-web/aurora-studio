# Написать пользовательскую историю (ручной аналог `make:create us`)

Сначала соберите контекст: `python3 .opencode/scripts/ctx_pack.py "<тема>"`. Без него
ассистент будет опираться на догадки, а не на проверенные карточки.

Скопируйте в чат, подставьте своё вместо фигурных скобок и приложите context pack:

---

Ты — системный аналитик проекта {{ПРОЕКТ}}. Напиши пользовательскую историю по шаблону
`Templates/UserStory_template.md`.

**Тема:** {{что должно появиться в системе}}

**Роль-адресат:** {{кто пользователь этой возможности}}

**Зачем:** {{какую задачу пользователя закрываем, какую боль убираем}}

**Границы:** {{что в объём не входит — это важнее, чем кажется}}

**Контекст из базы знаний:** {{вставьте сюда context pack}}

Правила:

1. Опирайся **только** на карточки со статусом `verified` из приложенного контекста.
   Всё, чего в контексте нет, — открытый вопрос, а не додуманный факт.
2. Термины бери из глоссария проекта, не изобретай синонимы.
3. Сценарии формулируй проверяемо: «когда <триггер>, система должна <реакция>».
4. В конце перечисли:
   - **Основания** — какие карточки использованы (пойдут в поле `based_on`);
   - **Открытые вопросы** — чего не хватило в базе, чтобы дописать историю;
   - **Предположения** — если что-то додумано, это должно быть названо явно.
5. Не пиши критерии приёмки внутри истории — они оформляются отдельно
   (`Prompts/AC_new.md`), иначе одно начинает противоречить другому при правках.

---

Готовую историю положите в `Artifacts/us/`. Название файла должно совпадать с названием
задачи в Jira — по нему собирается связь: `sync:jira-status` сопоставит их и покажет
расхождение, если одну из сторон переименуют.

# Промпт: спецификация API по коду

Ты пишешь спецификацию HTTP API по фрагментам кода. Шаблон: `TemplatesCode/cr-api_v1.0.md`.

## Что писать

- Маршруты: метод, путь, обработчик, авторизация. Строки таблицы уже заполнены кодом; не переписывай их.
- Для каждого маршрута: параметры пути и query, тело запроса, DTO, коды ответов, ошибки.
- Валидация: только исполняемые проверки. Комментарий, TODO и аннотация без обработчика не считаются.
- Авторизация: роль или область из аннотации. Закомментированную защиту называй «в коде отключена».

## Чего не делать

- Не добавлять маршруты, которых нет во фрагментах.
- Не писать «200 по умолчанию», если код его не возвращает.
- Не пересказывать README и комментарии как контракт.
- Не предлагать исправления и не описывать «как надо».

## Формат

Каждое утверждение заканчивай `[cN]`. В конце обязательный раздел «Что не удалось установить по коду»: внешние соглашения, SLA, поведение за границей сервиса.

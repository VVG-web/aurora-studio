# Промпт: схема данных по коду

Ты пишешь схему данных по DDL, сущностям, миграциям и запросам. Шаблон: `TemplatesCode/cr-data_v1.0.md`.

## Что писать

- Таблицы и колонки: имя, тип, PK, FK, NULL, уникальность, значение по умолчанию.
- Источник каждой строки: `ddl`, `entity`, `migration` или `query`. Не смешивай источники.
- Связи: только подтверждённые FK или однозначные обращения в коде.
- Где читается и пишется: обработчик и таблица. Динамический запрос без видимой таблицы называй «не видно».

## Чего не делать

- Не выдумывать индексы, которых нет в миграциях.
- Не считать сущность без `@Table` автоматически таблицей.
- Не писать «данные не удаляются», если в коде этого не видно.
- Не выводить тип из имени поля.

## Формат

Каждое утверждение с `[cN]`. В конце обязательный раздел «Что не удалось установить по коду»: объём, ретеншн, партиционирование, внешние ключи без DDL.

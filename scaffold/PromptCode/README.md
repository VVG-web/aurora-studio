# Промпты артефактов по коду (`PromptCode/`)

Правила письма для видов артефактов по коду. Шаблон задаёт форму, промпт — как писать: только факты из фрагментов, теги `[cN]`, обязательный раздел «Что не удалось установить по коду».

- **Что класть:** Один файл на вид, `<вид>.md` (например, `cr-api.md`); имя по умолчанию совпадает с видом.
- **Чего не класть:** Шаблоны (они в `TemplatesCode/`), готовые документы, промпты других задач (они в `Prompts/`).
- **Кто пишет:** Человек — правит под стиль проекта; базовые поставляет кит.
- **Вложенные папки:** Не заводите: движок ищет промпты только в самой папке.

# PromptCode: промпты артефактов по коду

Один файл — один промпт вида. Имя по умолчанию: `<kind>.md`, например `cr-api.md`.

Промпт читает движок, когда собирает артефакт по коду. Шаблон задаёт **форму**, промпт
задаёт **правила письма**. Меняйте промпт, если у проекта свой стиль, свои термины или
свой уровень строгости. Шаблон при этом можно не трогать.

## Общие правила для всех промптов

1. Только факты из показанных фрагментов кода. Каждое утверждение заканчивается тегом
   `[cN]`, где `cN` — номер фрагмента.
2. Не выдумывать имена классов, методов, полей, таблиц, топиков, ключей и значений.
   Если имени нет во фрагментах, его нет в документе.
3. Числа, статусы, коды ошибок, единицы и значения по умолчанию писать дословно.
4. Не предлагать исправления, не описывать, «как надо было бы». Документ описывает
   «как сделано», а не ревью.
5. Чего не видно в показанном, писать в раздел «Что не удалось установить по коду».
   Пустой раздел — законный ответ.
6. Не пересказывать комментарии, TODO, закомментированный код и тесты как исполнение.
   Это не доказательство работы.
7. Секреты не цитировать. Если в значении был секрет, движок уже заменил его маской.
8. Таблицы и каркас, заполненные кодом, не переписывать. Модель пишет только то, что
   требует объяснения.

## Проверка

```bash
python3 .aurora/scripts/code_artifacts.py --check
```

`--check` называет промпт, которого нет, и вид, у которого промпт пуст.

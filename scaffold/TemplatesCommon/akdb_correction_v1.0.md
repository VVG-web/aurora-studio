<!-- ============================================================
     ПРАВИЛА ДЛЯ ИИ: тип correction — Исправление (запись)
     ============================================================

ЖАНР. Исправление — короткий документ своими словами: какая карточка, что в ней неверно и как на
самом деле. Это непреложная правда с высшим приоритетом: она побеждает любой источник и применяется
при каждой сборке, поэтому переживает пересборку базы. Правка самой карточки руками не переживёт
`kb:reset` — исправление переживёт.

1. РАЗДЕЛЕНИЕ ОТВЕТСТВЕННОСТИ:

   | Часть | Что в ней живёт | Чего в ней быть НЕ должно |
   |---|---|---|
   | Шапка | чью карточку исправляют (`corrects`), дата, статус | оценок, причин |
   | Текст | утверждение в виде, пригодном для тезиса: что на самом деле верно; при необходимости — что именно неверно в источнике | «см. выше», ссылок на устное; чужих цитат без указания, откуда они |

2. КОГДА ПИСАТЬ ИСПРАВЛЕНИЕ, А КОГДА НЕТ:
   - в источнике ошибка, а человек знает, как верно, — исправление;
   - два источника равного класса расходятся и человек знает, какой верен, — исправление;
   - ответа на спор нет ни у кого — это вопрос (question), а не исправление;
   - принят выбор из вариантов с обоснованием — решение (decision).

3. КАК ПИСАТЬ. Одно исправление — один факт (или один связный вывод). Формулируйте так, чтобы текст можно
   было вставить в тезис карточки без правки: «Срок подтверждения заявки — три рабочих дня». Заголовки внутри
   текста допустимы — движок сдвинет их на три уровня вниз.

4. ПО ИМЕНИ. `corrects` называет карточку по её имени, `[[Имя]]`; можно списком. Имя меняется при
   слиянии и переименовании: движок находит карточку по прежнему имени, синониму и цепочке
   `superseded_by`.

5. ВИД КАРТОЧКИ. Поле `kind` в исправлении — слово человека о виде карточки (`knowledge`, `dictionary`,
   `document`): так человек задаёт вид, который движок иначе вычисляет сам.

6. СНЯТИЕ. Исправление, потерявшее силу, снимают командой `kb:correct --retire <имя> --reason "…"`
   (причина обязательна), файл не удаляют. Если источник карточки обновлён позже исправления,
   `kb:correct --check` пометит исправление «под вопросом»: решает человек, движок — нет.

7. НЕ ИСПРАВЛЕНИЕ. Правка закона, подписанного контракта, письма заказчика, стенограммы — нельзя: это
   доказательная часть. Исправление к карточке `cited-document` не применяется.
     ============================================================ -->

## Общие правила для всех карточек базы знаний

1. **Карточка — сущность, а не пересказ документа.** Про один предмет — одна карточка; знание из разных источников накапливается в ней. Перед созданием найдите карточку по имени и синониму и дополните её. Если внутри объясняется другая сущность — вынесите её в свою карточку, на месте оставьте ссылку.
2. **Только то, что есть в источнике.** Ни одного факта из общих знаний. Числа, сроки, коды, названия систем, ролей и статусов — дословно. Нет данных — раздел не пишется: пустых разделов и заглушек «нет данных» в карточке нет.
3. **Первая строка — определение.** Что это и чем отличается от соседнего — одной–двумя фразами. Дальше — существенное: условия, границы, исключения. Вёрстку источника, «см. рисунок», «в данной статье», номера разделов и повторы не переносите.
4. **Стиль.** Деловой русский, настоящее время, подлежащее — сама сущность. Без оценок, разговорных оборотов, вопросов в тексте и обращений к читателю. Термины проекта — как в источнике, без синонимов.
5. **Связи — часть мысли.** Каждое упоминание другой сущности — ссылка `[[Имя-карточки]]`; связь называется глаголом («входит в», «использует», «формирует», «ограничивает», «заменяет»), а не «см. также». Существование цели не проверяйте — пустышку заведёт движок. Ссылок на себя нет; карточка `knowledge` не ссылается на `deprecated`. Поле `related:` ведёт движок — вручную не заполняйте.
6. **Расхождения.** Источники говорят разное об одном факте — не усредняйте и не выбирайте «правдоподобное». Раздел `## Расхождения` пишет код по результату проверки: в тексте остаётся значение источника более доверенного класса, при равных классах — оба значения с указанием источников.
7. **Слово человека побеждает.** Если у карточки есть раздел `## Исправления человеком`, его текст — непреложная правда: утверждение из исправления помечается «(исправление человека)» и не выбрасывается.
8. **Встреча.** Знание из `Raw/meetings/` — только решения, факты, требования, ответы; каждое утверждение помечено «(встреча ДД.ММ.ГГГГ)», карточка несёт пометку `> 🎙 Из встречи …`. Шутки, рассуждения вслух и организационные реплики — не знание.
9. **Хвост карточки служебный.** Порядок и названия: `## Под вопросом` → `## Источник (перенесено дословно)` → `## Исправления человеком` → `## История изменений` → `## Слияние`. Свои служебные разделы не придумываются; хвост ведёт движок.
10. **Шапка.** Поля с пометкой «ставит движок» руками не меняются. Значения — только из перечисленных в шаблоне. Лишних полей нет. Даты — `ГГГГ-ММ-ДД`. Поле `template` называет файл этого шаблона.
11. **Что не живёт в карточке:** артефакты (US, AC, Epic, ревью, отчёты), задачи и планы работ, мнения и догадки, персональные данные людей, секреты и ключи, определение чужой сущности (вместо него — ссылка).
12. **Не подходит ни один шаблон — карточку не создавайте.** Ответьте `type: none` и назовите причину; придумывать тип нельзя.

## Шапка карточки

````yaml akdb-frontmatter-raw
---
corrects: "[[{{Имя карточки}}]]"         # Какую карточку исправляет; допустим список ["[[A]]", "[[B]]"]. Нет поля — движок попробует найти карточку по заголовку и допишет corrects_found: auto.
template: akdb_correction_v1.0.md        # СТАВИТ kb:correct --new. Файл этого шаблона. У прежних исправлений поля нет — это допустимо, они применяются как раньше.
created: {{ГГГГ-ММ-ДД}}                  # Дата написания; по ней сравнивается обновление источника.
status: active                           # active | archived. Снимает kb:correct --retire.
kind:                                    # Необязательно: knowledge | dictionary | document — слово человека о виде карточки.
---
````

Поля `template`, `corrects_found`, `archived`, `archived_reason` ставит движок (`kb:correct`). Файл исправления, который человек положил в `Raw/corrections/` руками и в котором нет `template`, действует так же — отсутствие поля не ошибка.

## Тело карточки

````markdown akdb-body
# Исправление: {{Имя карточки}}

{{Что на самом деле верно — в виде, пригодном для тезиса. При необходимости: что именно неверно в источнике.}}
````

## Пример

````markdown akdb-example
---
corrects: "[[Заявка на поставку]]"
template: akdb_correction_v1.0.md
created: 2026-10-01
status: active
---

# Исправление: Заявка на поставку

Срок подтверждения заявки на поставку — три рабочих дня. Значение «пять рабочих дней» в описании процесса устарело и действует только для заявок, зарегистрированных до 2026-09-01.
````

## Чек-лист самопроверки

- [ ] Тип `correction` выбран по `Prompts/KB_classify.md`: человек знает, как верно, а источник неверен.
- [ ] Файл лежит в `Raw/corrections/`; в `corrects` названа существующая карточка.
- [ ] Текст — один факт, пригодный для вставки в тезис без правки.
- [ ] Исправляется не закон, не подписанный контракт, не письмо заказчика, не стенограмма.
- [ ] Нет `{{…}}`, комментариев `<!-- -->`, меток `[ПРИМЕР]`.

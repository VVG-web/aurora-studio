# TemplatesCommon — общие шаблоны документов

Готовые шаблоны, которые кит привозит в проект, чтобы не начинать работу с сочинения
шаблона. Взяли файл, заполнили по инструкциям внутри — документ готов.

Этот файл — инструкция и для человека, и для ИИ. Модель, открывшая эту папку, должна
прочитать его до того, как возьмёт шаблон в работу.

## Что здесь лежит

Каждый файл `*.md`, кроме этого, — **шаблон одного вида артефакта**. Шаблон не является
документом: это форма, набор инструкций и примеров, по которым документ создаётся.
Ничего из содержимого шаблона не переносится в готовый документ дословно, кроме
структуры разделов.

| Файл | Артефакт | Версия | Автор |
|---|---|---|---|
| `analitycal_report_v1.0.md` | Аналитическое заключение | 1.0 | Вадим Герасимов |
| `ac_v1.0.md` | Критерии приемки (AC к User Story) | 1.0 | Вадим Герасимов |

## Паспорт шаблона

У каждого шаблона в начале файла — YAML-frontmatter, его паспорт. Обязательные поля:

| Поле | Что значит |
|---|---|
| `artifact` | название артефакта, который производится по этому шаблону |
| `template` | идентификатор шаблона, общий для всех его версий (без номера) |
| `version` | версия шаблона; растёт при изменении формы |
| `file` | имя файла — версия входит в него намеренно |
| `author` | кто ведёт шаблон |
| `created` | дата заведения |
| `updated` | дата последней правки |

Пример:

```yaml
---
artifact: "Аналитическое заключение"
template: analitycal_report
version: "1.0"
file: analitycal_report_v1.0.md
author: "Вадим Герасимов"
created: 2026-09-05
updated: 2026-09-05
---
```

## Версии в имени файла

Версия шаблона — часть имени: `<template>_v<version>.md`. Старые версии не удаляются и
лежат рядом с новыми, потому что документы живут дольше шаблонов: заключение, начатое
по версии 1.0, дописывается по версии 1.0, даже когда в папке уже есть 2.0. Так же
устроена и сдача: заказчик, принявший форму, вправе ожидать её же в следующем документе.

Правило выбора версии: **берите наибольшую**, если человек не назвал другую. Назвал —
берите названную и не предлагайте «более новую» без просьбы.

## Инструкция для ИИ

1. **Найдите шаблон по артефакту.** Сопоставляйте запрос человека с полем `artifact`
   в паспортах, а не с именем файла. Нет подходящего — скажите об этом прямо и
   не подгоняйте чужой шаблон под другой вид документа.
2. **Возьмите наибольшую версию**, если версия не названа.
3. **Прочитайте файл целиком до первой строки документа.** Внутри шаблона есть блок
   глобальных правил и комментарии `<!-- ИНСТРУКЦИЯ: -->` перед разделами. Это
   обязательные требования к содержанию, а не пояснения.
4. **Заполните `{{плейсхолдеры}}` фактическими данными.** Данных нет — это повод
   спросить или записать пробел в раздел ограничений документа, а не выдумать
   правдоподобное значение.
5. **Удалите из готового документа** все служебные HTML-комментарии, блоки-примеры
   («[ПРИМЕР]») и разделы, помеченные как опциональные и неприменимые.
6. **Проверьте по чек-листу** в конце шаблона, если он там есть.
7. **Сохраните результат** в папку артефактов проекта (`Artifacts/`), а не сюда:
   в `TemplatesCommon/` лежат только шаблоны.
8. **Шаблон не редактируйте** в ходе создания документа. Нужна правка формы — это
   отдельная задача и новая версия шаблона (см. ниже).
9. В готовом документе **не оставляйте паспорт шаблона**: у артефакта своя шапка,
   заданная самим шаблоном. Сослаться на шаблон в служебном поле документа можно —
   значением `template` и `version`.

## Чем отличается от `Templates/`

| Папка | Кто ведёт | Что происходит при `kit:update` |
|---|---|---|
| `Templates/` | проект | ничего: это ваши шаблоны, доработанные под заказчика |
| `TemplatesCommon/` | кит | изменённый в ките файл ложится рядом как `<файл>.new` |

Разделены потому, что у папок разная судьба. Свой шаблон живёт по правилам одного
заказчика и меняется вместе с ним; общий — по правилам ремесла и улучшается для всех
сразу. Пока они лежали вместе, правка общего шаблона в ките до заведённых проектов не
доезжала никогда, а доработка под заказчика рисковала быть затёртой чужим обновлением.

Нужен свой вариант общего шаблона — скопируйте его в `Templates/` и правьте там.
Правка поверх `TemplatesCommon/` работает, но тогда обновление кита будет предлагать
`.new` на каждом запуске.

## Как добавить шаблон или версию

Общие шаблоны едут из кита, а не заводятся в проекте.

- **Новый шаблон**: положите файл в `scaffold/TemplatesCommon/` кита с полным
  паспортом, добавьте строку в таблицу «Что здесь лежит» и выпустите версию кита.
- **Новая версия существующего**: скопируйте файл под новым именем
  `<template>_v<version>.md`, поднимите `version`, `file` и `updated` в паспорте.
  Старый файл оставьте на месте — по нему дописывают начатые документы.
- Шаблон, нужный только вашему проекту, — это `Templates/`, а не эта папка.

<!-- ============================================================
     ПРАВИЛА ДЛЯ ИИ: тип reference — Справочник
     ============================================================

ЖАНР. Справочник — таблица или перечень значений: коды, классификаторы, перечисления,
сопоставления полей. Ценность — точность, поэтому справочник переносится целиком, дословно, одной
карточкой на справочник. Модель даёт только имя и `summary`, тело не трогает.

ДВА ПРОИСХОЖДЕНИЯ ОДНОГО ТИПА:

а) ВЫВЕДЕННЫЙ ИЗ ИСТОЧНИКА (обычный). Справочник найден в `Sources/…` или в документе `Raw/…`.
   Карточку в `Reference/` собирает движок (`built: machine`, `kind: dictionary`). Руками не пишется.
б) РУКОПИСНЫЙ. Справочник, которого нет ни в одном источнике и который команда ведёт сама
   (сокращения, перечень смежных систем, сопоставление кодов). Мастер-файл — `Raw/reference/<имя>.md`,
   пишет человек; в `Reference/` движок строит его дословное зеркало (`built: machine`,
   `sources: ["Raw/reference/<имя>.md"]`). Правят мастер-файл, а не зеркало.

1. РАЗДЕЛЕНИЕ ОТВЕТСТВЕННОСТИ:

   | Часть | Что в ней живёт | Чего в ней быть НЕ должно |
   |---|---|---|
   | Заголовок и таблица | значения дословно, как в источнике; строки не переставляются и не сокращаются | пояснений, оценок, «исправленных» значений |
   | `summary` в шапке | одна фраза: что это за справочник и для чего | ссылок, чисел из таблицы |
   | `## Примечания` (только в мастер-файле) | пояснения человека к справочнику | значений таблицы |

2. ГРАНИЦЫ:
   - пояснение, что за величина и зачем она, — concept со ссылкой на справочник;
   - состояния с переходами — status-model (таблица статусов без переходов допустима как reference);
   - перечень значений внутри юридического документа — часть cited-document, а не reference.

3. КАЖДОЕ значение справочника — ровно как в источнике: регистр, знаки, коды, порядок строк.
   Ошибку в справочнике исправляют исправлением в `Raw/corrections/` (для мастер-файла — правкой
   мастер-файла).

## Общие правила для всех карточек базы знаний

1. **Карточка — сущность, а не пересказ документа.** Про один предмет — одна карточка; знание из разных источников накапливается в ней. Перед созданием найдите карточку по имени и синониму и дополните её. Если внутри объясняется другая сущность — вынесите её в свою карточку, на месте оставьте ссылку.
2. **Только то, что есть в источнике.** Ни одного факта из общих знаний. Числа, сроки, коды, названия систем, ролей и статусов — дословно. Нет данных — раздел не пишется: пустых разделов и заглушек «нет данных» в карточке нет.
3. **Первая строка — определение.** Что это и чем отличается от соседнего — одной–двумя фразами. Дальше — существенное: условия, границы, исключения. Вёрстку источника, «см. рисунок», «в данной статье», номера разделов и повторы не переносите.
4. **Стиль.** Деловой русский, настоящее время, подлежащее — сама сущность. Без оценок, разговорных оборотов, вопросов в тексте и обращений к читателю. Термины проекта — как в источнике, без синонимов.
5. **Связи — часть мысли.** Каждое упоминание другой сущности — ссылка `[[Имя-карточки]]`; связь называется глаголом («входит в», «использует», «формирует», «ограничивает», «заменяет»), а не «см. также». Существование цели не проверяйте — пустышку заведёт движок. Ссылок на себя нет; карточка `knowledge` не ссылается на `deprecated`. Поле `related:` ведёт движок — вручную не заполняйте.
6. **Расхождения.** Источники говорят разное об одном факте — не усредняйте и не выбирайте «правдоподобное». Раздел `## Расхождения` пишет код по результату проверки: в тексте остаётся значение источника более доверенного класса, при равных классах — оба значения с указанием источников.
7. **Слово человека побеждает.** Если у карточки есть раздел `## Исправления человеком`, его текст — непреложная правда: утверждение из исправления помечается «(исправление человека)» и не выбрасывается.
8. **Встреча.** Знание из `Raw/meetings/` — только решения, факты, требования, ответы; каждое утверждение помечено «(встреча ДД.ММ.ГГГГ)», карточка несёт пометку `> 🎙 Из встречи …`. Шутки, рассуждения вслух и организационные реплики — не знание.
9. **Хвост карточки служебный.** Порядок и названия: `## Под вопросом` → `## Источник (перенесено дословно)` → `## Исправления человеком` → `## История изменений` → `## Слияние`. Свои служебные разделы не придумываются; хвост ведёт движок.
10. **Шапка.** Поля с пометкой «ставит движок» руками не меняются. Значения — только из перечисленных в шаблоне. Лишних полей нет. Даты — `ГГГГ-ММ-ДД`. Поле `template` называет файл этого шаблона.
11. **Что не живёт в карточке:** артефакты (US, AC, Epic, ревью, отчёты), задачи и планы работ, мнения и догадки, персональные данные людей, секреты и ключи, определение чужой сущности (вместо него — ссылка).
12. **Не подходит ни один шаблон — карточку не создавайте.** Ответьте `type: none` и назовите причину; придумывать тип нельзя.

## Шапка карточки

Шапка карточки в `Reference/` (выводится из источника или зеркало мастер-файла):

````yaml akdb-frontmatter
---
title: "{{Название справочника}}"        # Как справочник называется в источнике. Совпадает с именем файла по правилам нормализации.
aliases: []                              # Код справочника (SPR-001), принятое сокращение.
tags: []                                 # Свободные метки.
type: reference                          # Не менять.
template: akdb_reference_v1.0.md         # СТАВИТ ДВИЖОК. Файл этого шаблона.
kind: dictionary                         # dictionary | document. Назначает kb:kind (раздел Reference → dictionary).
status: knowledge                        # knowledge | draft | placeholder | deprecated. СТАВИТ kb:trust.
summary: "{{одна фраза}}"                # Суть справочника, до 300 знаков. Пишет модель при разборе.
sources:                                 # СТАВИТ ДВИЖОК. Для зеркала мастер-файла — ["Raw/reference/<имя>.md"].
  - "{{путь источника}}"
source_synced: {{ГГГГ-ММ-ДД}}            # СТАВИТ ДВИЖОК.
created: {{ГГГГ-ММ-ДД}}
updated: {{ГГГГ-ММ-ДД}}
built: machine                           # СТАВИТ ДВИЖОК.
related: []                              # ВЕДЁТ ДВИЖОК (kb:links).
trust: {{raw|trusted|draft|unknown}}     # СТАВИТ kb:trust.
trust_basis: "{{словами}}"               # СТАВИТ kb:trust.
trust_checked: {{ГГГГ-ММ-ДД}}            # СТАВИТ kb:trust.
corrected_by: ""                         # СТАВИТ kb:correct (только у выведенных из источника).
---
````

Шапка **мастер-файла** `Raw/reference/<имя>.md` (пишет человек; остальные поля добавит зеркало):

````yaml akdb-frontmatter-raw
---
title: "{{Название справочника}}"        # Совпадает с именем мастер-файла.
aliases: []
tags: []
type: reference                          # Не менять.
template: akdb_reference_v1.0.md         # Файл этого шаблона.
kind: dictionary                         # dictionary — переносится целиком.
owner: "{{@автор}}"                      # Человек, который ведёт справочник.
summary: "{{одна фраза}}"
created: {{ГГГГ-ММ-ДД}}
updated: {{ГГГГ-ММ-ДД}}
---
````

## Тело карточки

````markdown akdb-body
# {{Название справочника}}

| {{Колонка 1}} | {{Колонка 2}} |
|---|---|
| {{значение}} | {{значение}} |

## Примечания
<!-- ИНСТРУКЦИЯ: ТОЛЬКО в мастер-файле, ОПЦИОНАЛЬНО. Пояснения человека к справочнику. В карточку,
     выведенную из источника, не добавляется. -->
{{пояснение}}
````

## Чек-лист самопроверки

- [ ] Тип `reference` выбран по `Prompts/KB_classify.md`; это таблица или перечень значений без связного текста.
- [ ] Значения перенесены дословно: регистр, знаки, коды, порядок строк.
- [ ] Рукописный справочник лежит в `Raw/reference/`, а не в `Reference/`.
- [ ] `summary` — одна фраза без ссылок и чисел из таблицы.
- [ ] Шапка: `template` называет этот файл; поля «ставит движок» не тронуты.
- [ ] Нет `{{…}}`, комментариев `<!-- -->`, меток `[ПРИМЕР]`.

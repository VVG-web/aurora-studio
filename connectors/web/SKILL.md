# Веб-страницы — {{PROJECT_NAME}}

## Зеркало делает скрипт, не модель

```bash
python3 .opencode/scripts/web_export.py            # показать, что будет выгружено
python3 .opencode/scripts/web_export.py --apply    # записать в кеш проекта
python3 .opencode/scripts/web_export.py --verify   # гейт детерминизма
python3 .opencode/scripts/web_export.py --prune --apply   # убрать файлы снятых ссылок
```

Модель страницы не переписывает. Одна и та же страница обязана давать байт-в-байт один
файл: иначе git показывает правки там, где их нет, а `sync:audit` не может проверить
состояние зеркала.

## Откуда берётся список

Блок `web:` в `aurora.config.yaml`. Правится в панели: «Зеркала» → «Веб-страницы».

```yaml
web:
  pages:
    - url: https://law.example/kodeks/nalogovyy
      trusted: true
    - url: https://blog.example/articles/000000
      trusted: false
```

Список веб-ссылок **не смешивается** со списком корней Confluence: это разные источники,
они настраиваются отдельными блоками и доверяются по разным правилам.

## Доверие ставится на каждую ссылку

Веб-страница — документ, а не задача. У задачи доверие вычисляется по её статусу; у
документа объявляется тем, кто его подключил. Закон, национальный стандарт, официальный
регламент — доверенные. Чужой блог, пересказ, статья на форуме — нет.

Галочка уходит в шапку сохранённого файла полем `trusted`, и `kb:trust` читает её
оттуда. Поэтому доверие остаётся свойством источника и не зависит от того, куда его
положили на диске.

Снять доверие можно в любой момент: следующий `sync:web` перепишет шапку, а ближайший
`kb:trust` переведёт выведенные из страницы карточки в черновики — с основанием словами.

## Что дальше

Выгруженные страницы разбираются в карточки обычным ходом: `kb:build` возьмёт их в план
наравне с прочими источниками, `agent:build` разложит на карточки.

Панель: `sync:web`

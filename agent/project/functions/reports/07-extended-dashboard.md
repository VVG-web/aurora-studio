# Extended Dashboard Function
## Description
`make_extended.py` собирает финальный артефакт: один самодостаточный HTML-файл
(`paths.OUTPUT_PATH`, по умолчанию `Artifacts/reports/{project}_analyst_extended.html`),
который открывается прямо с диска. Файл несёт метрики **всех посчитанных годов**
(`paths.years_built()`) в одном встроенном объекте `DATA`; переключатель периода в шапке
меняет активный год на клиенте — ни пересборки, ни повторной выгрузки ради смены года не
нужно. Сервер для просмотра и фильтров не требуется; Chart.js подгружается с публичного CDN
(`https://cdn.jsdelivr.net/npm/chart.js`) — в закрытом контуре файл кладётся рядом с
отчётом, и адрес в шаблоне заменяется на локальный (в шаблоне есть комментарий), таблицы
при этом работают и без графиков.

## Key Features
- **KPI-ряд** — суммарные переходы в «Аналитика готово»: истории / прочие артефакты /
  всего (с учётом BA-SA); в режиме «на 1 человека» — те же значения, делённые на
  человеко-недели.
- **Блок 1** — стек по неделям: переходы в «Аналитика - готово» (истории / прочие /
  BA-SA), поверх — линия тренда; вход «вес» (0.1–2, по умолчанию 0.5) множит столбцы
  «прочие» и BA-SA, переключатель масштаба «тотал / на 1 человека» делит каждую неделю
  на число аналитиков, давших в ней больше нуля (считается из `weekly_by_person`).
- **Блок 2** — таблица длительностей переходов историй между шестью парами этапов с
  выбираемой обрезкой по персентилем (кнопки 100/95/90/80/70, по умолчанию 95):
  N, среднее по обрезанной выборке, среднее по всей, Δ к среднему, медиана, граница
  персентиля.
- **Блок 3** — те же длительности по сотрудникам (при том же персентиле): зелёным
  подсвечен минимум столбца, красным — максимум, строки, склеенные из прежних написаний
  имени, помечены «≡»; под таблицей — сноска о склейке, в тултипе — прежнее ФИО и
  учётная запись.
- **Блоки 4–5** — Confluence: созданные страницы по неделям и «создание + правки»
  стеком по неделям, у обоих — линия тренда.
- **Фильтры** — мультивыпадающие списки с поиском внутри списка и мастер-флагом «Все»
  по типу задачи (История / BA-SA Task / Прочие), роли, человеку и неделе; применяются
  ко всем блокам на клиенте. При выборе конкретных людей или ролей суммы берутся из
  `weekly_by_person` (агрегированный `weekly` не годится), выбранные недели вне фильтра
  в блоке 1 рисуются нулями.
- **Полосы событий** — строки `events.csv` (недели дополняются нулём: «6» и «06» —
  одна и та же) рисуются вертикальными красными/жёлтыми полосами на недельных графиках
  с повёрнутыми подписями (`eventPlugin`); событие на несколько недель подписывается
  один раз, у начала полосы.
- **Переключатель периода** — строится только при ≥ 2 посчитанных годах; при переключении
  `DATA.jira` / `DATA.confluence` / `DATA.week_labels` перепоказываются на другой год,
  заново размечаются недели страниц Confluence (`stampPages`), сбрасываются фильтры
  (человек или неделя прошлого года в новом могут не существовать) и пересобираются
  справочники ролей/людей/недель.
- **Кнопки шапки** — «↻ Пересобрать дашборд»: через `serve_dashboard.py` ходит на
  `/__rebuild` и после готовности обновляет страницу; из файла же копирует в буфер
  готовую команду `python3 .opencode/scripts/report_analyst.py --skip-fetch` (без буфера —
  выделяет её текстом). Кнопки файлов настроек (roster / events / metrics) открывают
  файл в редакторе через `/__open/<name>`, «📁 Папка» — показывает папку через
  `/__reveal/roster`; без сервера кнопки показывают пути с копированием.
- **Карточка «Методология и ограничения»** — в самом отчёте зафиксировано, откуда
  Confluence-даты (REST с `expand=history`/`version`), что «аналитик закончил» —
  переход в «Аналитика - готово» по историям и первый переход в «Закрыто» по BA-SA Task.

## Implementation Notes
- Линия тренда подгоняется (линейная регрессия) только по **рабочему окну**: ведущие
  нулевые недели (до старта проекта) и хвостовые (ещё не наступившие) вырезаются
  (`trendWindow`), а текущая незавершённая неделя (`DATA.partial`) выбрасывается из
  подгонки, если стоит в конце окна (`partialIndex`); за окном линия не продлевается —
  `computeTrendLine` возвращает `null` на них.
- Страницы Confluence хранятся **один раз на все годы** (`shared_pages()`): раньше каждый
  год нёс свою копию — на семилетнем проекте один список из 1705 страниц лежал в файле
  семь раз (3,8 МБ из 4,5). Носитель — почта, вес важен. Недельную разметку браузер делает
  при каждом переключении периода (`stampPages`/`isoWeekOf`): номер недели зависит от
  выбранного года, а дата берётся, как записана в строке, без перевода в UTC — иначе
  страница, созданная в понедельник в 01:00 по местному, уезжала бы в прошлую неделю.
- Склейка прежних написаний (ростер «Прежние ФИО», разделитель — запятая) делается
  **до** агрегаций, на стороне генератора (`canon()`, карты `alias_of` / `aliases_of` /
  `account_of`); пустой исполнитель получает имя «Не назначен». Дашборд показывает
  склейку явно: метка «≡», тултип с прежними написаниями и учётной записью, сноска.
- Маркеры шаблона `__PROJECT__`, `__YEAR__`, `__SOURCES__` (хосты Jira/Confluence без
  схемы, `host()`), `__BUILT_AT__` подставляются `str.replace`; `__DATA__` — JSON с
  экранированием `</` → `<\/`, чтобы встроенный скрипт не рвал HTML.
- Подписи недель — «WW (dd.mm)», понедельник ISO-недели
  (`datetime.date.fromisocalendar(y, w, 1)`); 53-й недели нет не в каждом году — такие
  подписи молча пропускаются. Если год из `year:` конфига не посчитан, активным
  становится последний посчитанный (`YEARS[-1]`).

# Aurora Grill Function

## Description

Скилл aurora-grill разбирает замысел по дереву решений: раунды вопросов с рекомендациями,
пока не останется молчаливых допущений. Задача — не собрать требования, а найти решения,
которые иначе будут приняты **молча**: молчаливое допущение обходится дороже неверного,
потому что неверное видно и его исправляют, а молчаливое обнаруживается в готовом
документе, когда переделывать поздно. Планировщик Авроры использует его перед
производством артефакта (панель показывает вопросы и собирает ответы), человек — перед
крупной правкой движка или базы. Вызов — `/aurora-grill`.

## Key Features

- **Дерево решений с раундами** — замысел — это дерево решений, каждое ветвится на те, что
  от него зависят. **Фронтир** — решения, чьи предпосылки уже определены: вопросы, которые
  можно задать **сейчас**, не гадая об ответах, которых ещё не слышали. Раунд задаёт весь
  фронтир сразу; ответы человека перекраивают дерево — решённое выталкивает фронтир
  наружу и открывает вопросы, которые от него зависели. Вопрос, чей ответ зависит от
  другого **открытого** вопроса этого же раунда, уходит в следующий.
- **Форма вопроса** — пронумерованы, и рекомендация **обязательна**:

  ```
  ❓ Q1 — Название вопроса: суть, при необходимости с вариантами (а), (б), (в).

  ➡️ Рекомендую: вариант и почему именно он.
  ```

  Вопрос без рекомендации требует сочинить ответ с нуля — и получает либо молчание, либо
  первое пришедшее в голову. С рекомендацией на вопрос отвечают одним словом: «да», «б»,
  «не так — вот почему».
- **Факты ищет спрашивающий, а не человек** — всё, что можно узнать из файлов, конфига,
  базы знаний и предыдущих прогонов, узнаётся самостоятельно; у человека спрашивают
  **решения**, а не сведения.
- **Правила** — не больше одного раунда за раз (список из тридцати вопросов — анкета, а не
  разбор); возражение — это ответ (дерево пересобирается, а не продавливается); разбор
  кончается пустым фронтиром, а не усталостью; итог проговаривается вслух и
  подтверждается человеком, прежде чем что-то делать.
- **Ранний стоп допустим** — человек может сказать «хватит, работай» на любом раунде, и
  это не провал разбора: план строится по тому, что уже известно, а невыясненное
  называется в нём прямо, а не заполняется догадками. В артефакте это видно буквально:
  неотвеченные вопросы становятся строками раздела «Допущения» с пометкой, что
  предположил движок, а не модель.

## Implementation Notes

Планировщику можно дать MCP-сервер с поиском в интернете (`outbound: true`) — но наружу
уходит **вопрос про механику**, а не задача: сторож не пропускает запрос, в котором есть
четыре слова подряд из задачи, пака или названий карточек, и режет всё длиннее пятнадцати
слов («как устроен идемпотентный retry в Kafka» проходит, пересказ требований заказчика —
нет). Отказ объясняется вслух: молчаливая пустота будет истолкована как «в интернете
ничего нет», и на этом ложном знании построится план. Это порог, а не стена — пересказ
задачи своими словами сторож не поймает; для закрытого контура правильный выбор — не
давать планировщику `outbound`-серверов вовсе.

Метод — приём дерева решений с раундами — взят из практики стресс-теста замыслов в Claude
Code (навыки `grilling` / `grill-me`) и изложен под задачу Авроры. Имя намеренно своё:
установка скиллов перезаписывает одноимённые папки в `~/.claude/skills/`, и `grill-me` там
у многих уже стоит — своя, доработанная; чужую настройку ради единообразия имени движок не
затрёт.

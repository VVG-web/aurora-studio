# Built-In Agent Commands Function

## Description

Командная группа `agent:` — поверхность, через которую аналитик запускает встроенный
LLM-агент: замер шлюзов, ping цепочки бэкендов, разбор партий источников на карточки,
дистилляция тезисов, производство артефакта через полный пайплайн, разбор конфликтов
синонимов и ответы на вопросы по базе. Две поверхности: диагностика цепочки —
`agent_core.py` (панель: `agent:ping`, `agent:width`), задачи агента — `agent_runner.py`
(панель: `agent:aliases`, `agent:build`, `agent:ask`, `agent:distill`, `agent:make`).
Команды — модель-драйвенное дополнение скриптовых `kb:` команд: скрипт подготавливает и
проверяет, агент судит.

## Key Features

- **`agent:ping`** — проверить цепочку моделей живым запросом: каждый бэкенд отдельно —
  жив, занят (слот в работе), пуст; время ответа и образчик. Пустой ответ считается
  отказом: бэкенд с HTTP 200 и пустым текстом (chat-шаблон на сервере) считается мёртвым.
  Отдельной строкой — эмбеддинги (свой сервис или кольцо); без них поиск идёт по словам,
  это рабочее состояние.
- **`agent:width`** — замерить, сколько одновременных запросов держит каждый шлюз: число
  известно ниоткуда, поэтому меряется, а не спрашивается. Короткие запросы волнами, ступени
  от 1 до 32, пока растёт пропускная способность; перестала расти — дальше шлюз ставит в
  очередь, и потоки добавлять бессмысленно. Плоская скорость — это ответ, а не «ширина 2»:
  такому шлюзу потоки не помогут, выигрыш ищут в других шлюзах кольца.
- **`agent:aliases`** — конфликты синонимов: воркер судит по **содержанию** карточек, а не
  по именам, и предлагает либо осмысленные уточнения («distinct»), либо честно назвать
  дубль. Дубли агент не сливает — знание можно потерять, дубль откладывается человеку
  (`kb:dedupe` — его). Критик проверяет предложение до записи; оракул — линтер,
  пересчитывающий конфликты. Успех — не «ноль конфликтов любой ценой» (часть из них —
  именно дубли), а «каждый конфликт разобран»: уточнён или честно отложен.
- **`agent:build`** — разбор плана источников на карточки: модель решает ровно две вещи —
  **где границы темы** и **как она называется**; тела переносит движок дословно, раздел
  базы выбирается по существу. Арифметическая проверка (секции не пересекаются, служебные
  секции не попали) и критик до записи. Источник без заголовков: границы предлагает
  планировщик по описи абзацев, либо источник откладывается человеку с честной отметкой
  «ОТЛОЖЕНО ЧЕЛОВЕКУ» (возврат — `kb:build --reopen`). `--until-done` — весь план, партия
  за партией, у каждой свой чекпойнт и коммит (первичная сборка: часы, потолок `--hours`);
  обрыв связи прогон не роняет — ждёт и продолжает с того же места.
- **`agent:distill`** — тезисы для карточек `knowledge`: модель пишет определение,
  дословный исходный текст уходит под тезис в раздел «Источник (перенесено дословно)» —
  потерянное лежит строкой ниже, и его можно сверить. Каждый тезис проверяет **Момус**;
  длинный источник режется не более чем на три части (map-reduce, Момус проверяет и
  части, и итог). `dictionary`/`document` **никогда не переписываются**: тело переросло
  окно — планировщик предлагает границы нарезки, движок режет дословно, а карточка
  превращается в карту документа (`status: index`, части получают `part_of` и ссылки на
  соседей).
- **`agent:make`** — производство артефакта по типу из реестра проекта
  (`aurora.config.yaml`): обогащение базой (`ctx_pack.py`) → **планировщик** с
  пронумерованными вопросами к аналитику (к каждому — рекомендация, чтобы отвечали одним
  словом; метод разбора замысла — из скила `aurora-grill`) → **воркер** (документ по плану
  и форме) → **критик** (форма, план, `coverage` по пяти осям) → **Момус** (правдивость).
  Состояние — в `Workspaces/<сессия>/session.json` и в шапке документа (`pipeline:`) —
  после прерывания производство продолжается с того же места (`--session`). Ответы
  аналитика записываются в «Уточнения» немедленно после получения; молчаливо принятые
  решения — в «Допущения» с источником («решила модель» / «не спросили»). Кнопка
  «Хватит, работай» (`--enough`) строит план по известному и называет в нём
  невыясненное. Документ получает `status: ready` только если прошёл все проверки без
  находок Момуса; утверждения без опоры уходят в «Под вопросом» и в чистовик не
  переносятся.
- **`agent:ask`** — вопрос к базе своими словами: движок собирает пак (`ctx_pack.py`,
  фильтр карточек `--mode generate|ask|evaluate|review`), модель отвечает только по
  карточкам и после каждого утверждения ставит `[[ссылку]]` — без ссылки утверждение
  считается выдуманным; «в базе этого нет» — допустимый и честный ответ. Ответ
  проверяет **Момус** (роль `qa`); разговор пишется в `AuroraKnowledgeDB/meta/ask/` и
  уходит в git вместе с карточками — память команды: второй аналитик видит, что уже
  спрашивали. Уточнение без потери контекста — `--thread ID` (в контекст уходят последние
  четыре пары разговора), список разговоров — `--threads`, конкретный бэкенд —
  `--backend N`, отмена журнала — `--no-journal`.
- **Общие флаги задач** (`agent_runner.py`): `--apply` — записывать в базу (без него —
  предпросмотр, ничего не записано), `--critic` — проверка второй моделью до записи
  (обязателен в проде), `--limit N` — первые N конфликтов/источников для пробы,
  `--no-checkpoint`, `--no-momus`, `--hours` (для `--until-done`).
- **Конфигурация, которую ставит оператор** (общая для всех команд группы): кольцо
  бэкендов в панели «Настройка» → «Агент» или в `.env.aurora.local` — у каждого бэкенда
  объявленное контекстное окно, чтобы очевидно большой запрос ушёл к модели с более
  широким окном, а не убил провайдера ошибкой; ширина `WIDTH` — предел конкретного шлюза,
  `AURORA_AGENT_PARALLEL` — потолок всего прогона (`авто` — сумма объявленных ширин);
  рассуждения по ролям — пересказ извлекает и без них, критик и Момус судят и им они
  нужны; исходящие MCP-серверы (`outbound: true`) — запросы только про механику, сторож
  закрыт по умолчанию, журнал — `Workspaces/_outbound.md`.

## Implementation Notes

Движковая реализация (кольцо, адаптер, цикл worker/critic/oracle, чекпойнты) описана в
[обзоре модуля](./01-built-in-agent.md); здесь — командная поверхность и смысл флагов.
Все команды запускаются из корня проекта (там, где есть `AuroraKnowledgeDB/`); движок
команд ищется в `.opencode/scripts/` проекта, затем в ките. `--json` у `agent_core` —
машинный вывод, по которому панель разбирает результат. Пайплайн `agent:make`
(`based_on`, «Уточнения», «Допущения», «Под вопросом», `coverage`) также встречается в
модуле скила aurora-vault (production) — там он описан как часть воркфлоу производства
артефактов, здесь — как команда.

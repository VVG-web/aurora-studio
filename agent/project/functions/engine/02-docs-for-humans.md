# Docs for Humans Function

## Description

Каталог `docs/readme/` — «для глаз» документация фреймворка: короткий упорядоченный путь чтения для людей (аналитики, владелец продукта, разработчики), а не технический справочник. Он намеренно отделён от справочника команд (`docs/commands.md`), устройств движка (`docs/IMPLEMENTATION.md`, `docs/CONTRIBUTING.md`) и процедур для ассистента (`skills/aurora-vault/references/`). Набор актуален для kit **1.12.0** (по README самого каталога). Индекс `docs/readme/README.md` перечисляет шесть документов в порядке чтения и объясняет, когда каждый становится нужным: первый день → первая неделя → появился второй аналитик → пошла разработка по вашим спекам.

## Key Features

- **`docs/readme/01-overview.md`** — всем участникам: зачем нужен фреймворк (три способа, которыми ломается работа ИИ без модели доверия: «сам написал — сам поверил», потеря истории, тихое устаревание), три принципа (артефакт ≠ знание, ничего не удаляется, проверенное меняет только человек), карта слоёв доверия по папкам, жизненный цикл карточки `imported` / `draft` / `in-review` / `verified` / `deprecated` (`verified` — верхний статус базы), неизменяемый журнал Decision Records (хранятся и отклонённые варианты) и диаграмма круговорота знаний.
- **`docs/readme/02-quickstart.md`** — новичку в первый день, «база знаний за один день»: пять правил (работать в `Workspaces/` и `Artifacts/`; не трогать руками `Sources/` и `Raw/`; светофор из трёх состояний вместо пяти статусов; не удалять, а заменять через `kb:supersede`; у `verified`-карточки есть `owner` и `review_by`), три команды на каждый день (`ctx_pack.py "тема"`, `kb_lint.py --summary`, `aurora_stats.py`), одна привычка (завести карточку в момент, когда узнали что-то нового) и таблица «что отложить, когда понадобится».
- **`docs/readme/03-team-rules.md`** — для команд с несколькими аналитиками: роли и владение, ритуалы, правила Decision Records, правила «никогда», работа в git, чеклист качества карточки.
- **`docs/readme/04-practice.md`** — всем, кто работает с базой: таблицы «ситуация → команда», правило запуска, ручной путь через `Prompts/` в любом чате и что делать, когда команда ругается. Две линии работы: команды ассистента `/aurora-vault …` и прямой запуск скриптов движка.
- **`docs/readme/05-gardening.md`** — дежурному по базе, ментальная модель «база — это сад, а не куча файлов»: шкала доверия, как знания попадают в сад (наполнение), как зреют (верификация), разбор дрейфа, прополка, ритм недели и три правила, которые нельзя нарушать.
- **`docs/readme/06-sdd.md`** — Spec-Driven Development для аналитиков и подрядчиков: спека как карточка знаний и исполняемый контракт, цепочка трассировки (ТЗ → REQ → SPEC → Jira → AC → ПМИ), DoR-гейт передачи, `spec-pack` как мост к внешней разработке, проверка результата и цикл изменений.

## Implementation Notes

Кластер — чистая проза, кода нет: в каталоге только индекс `README.md` и шесть нумерованных документов. Индекс явно перечисляет, чего здесь нет: установка и настройки — `docs/INSTALL.md`, справочник команд с модификаторами — `docs/commands.md` или `python3 aurora.py list <проект>`, устройства движка — `docs/IMPLEMENTATION.md` и `docs/CONTRIBUTING.md`, процедуры ассистента — `skills/aurora-vault/references/`. Число 1.12.0 как актуальность набора взято из README каталога.

Язык набора — русский, целевая аудитория — команда проекта; deploy-кластер (`docs/INSTALL.md`, `docs/IMPLEMENTATION.md`) написан по-английски. Дублировать справочник намеренно не пытаются: каждый из шести документов отвечает за один слой «что/почему/как начать», а не за реестр команд.

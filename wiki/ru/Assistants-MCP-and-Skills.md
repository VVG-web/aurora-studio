# Ассистенты, MCP и скиллы

[Wiki](README.md) · см. также: [Спросить базу](Asking-the-Base.md) · [Доверие](Trust.md) · устройство:
[architecture, раздел 5](../../docs/architecture.md)

Аврора встречает ассистентов (Claude Code, Cursor, OpenCode, любой клиент MCP) двумя способами: **MCP** отдаёт им базу как
инструмент, а **скиллы** учат их процедурам.

## Сервер MCP

`scripts/aurora_mcp.py` — небольшой stdio-сервер (JSON-RPC 2.0, только стандартная библиотека — ни SDK, ни Node). Он
позволяет ассистенту искать в базе, читать карточки и задавать вопросы, пока тот работает над вашей задачей, вместо того
чтобы вы носили контекст в чат руками.

| Инструмент | Делает |
|---|---|
| `kb_search` | найти карточки по смыслу и словам — имя, статус доверия, суть |
| `kb_card` | прочитать карточку целиком |
| `kb_context` | собрать пакет контекста по теме (режим `generate` — только доверенное знание) |
| `kb_index` | оглавление базы: строка на карточку, по разделам |
| `artifact_spec` | как делать артефакт этого проекта: шаблон, папка, промпт, граница чистовика |
| `kb_ask` | спросить базу: модель проекта отвечает по карточкам со ссылками (медленно — десятки секунд) |

**Он только читает.** Ассистент не проходит git-guard и не участвует в доверии — доверие считает движок по задачам, а не
ассистент. `kb_ask` не пишет журнал разговора; файлов он не меняет.

**Один сервер — одна база.** Заказчики не должны смешиваться: сервер запускается на проект (`--project <корень>`), и в его
имени стоит слаг проекта (`aurora-<слаг>`), поэтому `aurora-alpha.kb_search` не спутать с `aurora-beta.kb_search`.
Неудавшийся вызов возвращает `isError: true` и причину словами (неизвестный инструмент, карточки нет, режим вне перечня), а
не простыню `usage`.

### Подключение

`kit:mcp` (или `python3 aurora.py mcp`) проверяет сервер и печатает готовый блок подключения на каждый проект машины. Формат
один для всех клиентов:

```json
{"mcpServers": {
  "aurora-alpha": {"command": "python3",
                   "args": ["<проект>/.opencode/scripts/aurora_mcp.py", "--project", "<проект>"]}}}
```

Серверы машины (общие для всех проектов) лежат в `local/mcp.json` кита; свои у проекта — в `mcp.json` проекта. Раздел
панели **Настройки проекта** правит оба; секреты в `mcp.json` проекта не попадают (он уходит в git). Самопроверка без
ассистента: `python3 .opencode/scripts/aurora_mcp.py --selftest`.

## Скиллы

С китом едут три скилла (`skills/`):

| Скилл | Для чего |
|---|---|
| `aurora-vault` | работа с фреймворком: построение и ведение базы, доверие, Decision Records, ревью и генерация артефактов; справки-процедуры за «процедурными» командами |
| `aurora-grill` | разбор замысла по дереву решений: раунды вопросов с рекомендациями, пока не останется молчаливых допущений. Планировщик запускает его перед производством артефакта; доступен и в чате |
| `aurora-dev` | разработка самого движка: прогон тестов и сценариев, покрытие изменений. Не для проектов, которые просто пользуются Авророй |

Скиллы — **копии**, а не ссылки на репозиторий: ставьте их командой `kit:skills --apply` в `~/.claude/skills/` (остальные
harness получают ссылку на эту папку). `aurora.py new` делает это сам, а `aurora.py update --apply` обновляет. Установка
скилла никогда не оставляет агента без него: новая копия делается рядом со старой и подменяет её.

В диалоге `/aurora-vault <команда>` запускает команду-процедуру (`kb:ingest`, `kb:decide`, `make:create`, …) — работу, которой
нужен смысл, а не скрипт. Упоминания в задаче: `@путь` (файл или папка проекта), `/скилл` (его метод уходит в задачу),
`@сервер` (сразу подключается MCP-сервер).

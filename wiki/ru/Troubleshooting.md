# Если что-то не так

[Wiki](README.md) · см. также: [Частые вопросы](FAQ.md) · [Windows и macOS](Windows-and-macOS.md) · начните с `kit:doctor`

Скрипты движка объясняют причину, а не просто падают. Частые случаи:

## Перед запуском

| Симптом | Причина и что делать |
|---|---|
| **«git-guard: N незакоммиченных файлов»** | Массовая запись по грязному дереву не оставляет возможности отката. Закоммитьте работу (панель: *Закоммитить*) — либо, если понимаете риск, добавьте `--allow-dirty`. |
| **Агент отказывается писать: нет git** | Пишущий запуск сначала коммитит контрольную точку. Нет репозитория — некуда откатываться. `git init` и первый коммит всей базы. |
| **«уже идёт пишущий прогон»** | Один пишущий на проект. Сообщение называет pid и время старта владельца. Если процесс мёртв, блокировка снимается сама; если жив — подождите или остановите его. |
| **`kb_lint: нет папки AuroraKnowledgeDB/`** | Вы запустили из кита, а не из корня проекта. |
| **Агент не видит `AGENTS.md`** | Откройте **папку проекта** как корень рабочей области, а не кит. |
| **`/aurora-vault` не находится в разговоре** | Скилл — копия в `~/.claude/skills`: `kit:skills --apply`. |

## Синхронизация

| Симптом | Причина и что делать |
|---|---|
| **Синк не начался: «VPN-1 недоступен» / код 2 / строка `AURORA-NET {…}`** | Проверка соединения включена, профиль источника не отвечает — скрипт отказал до первого запроса, а не упал таймаутом. Поднимите VPN и запустите снова либо поставьте запуск в очередь в диалоге панели. `net:status` показывает состояние, `net:probe` проверяет сейчас. |
| **«нет токена — задайте CONFLUENCE_PERSONAL_TOKEN»** | Скрипты синхронизации ходят в Confluence и Jira напрямую; MCP вашего редактора не помогает. Скопируйте `aurora.env.local.example` в `.env.aurora.local` и заполните. Проверка: `python3 .aurora/scripts/jira_export.py --limit 1`. |
| **Скилл синхронизации смотрит не в то пространство или JQL** | Значения живут в `aurora.config.yaml`, а не в скилле: поправьте конфиг или запустите `aurora_setup.py` ещё раз. |
| **Таймауты, половины страниц нет** | Страницы, до которых обход не дошёл, остаются в состоянии; запустите синхронизацию снова. `--prune` отказывается удалять после выгрузки с ошибками. |
| **Страницу перенесли в Confluence** | `kit:remap-sources`, затем `kb:repair --gone-sources`. |
| **В зеркале нет поддерева, а в вебе страница видна** | Прочитайте вывод синка: `ветка <название>: сервер отдал N из M` или `отказ 403` называет ветку, которую сервер не отдал (права токена, перенос страницы), а строка корня показывает, до какой глубины дошёл обход. `sync:confluence --diagnose-tree` печатает дерево с числом детей у страниц и ничего не пишет. Та же картина бывает при неполном движке проекта: его называет `kit:doctor`. |
| **«Длинные пути: не всё будет загружено» в начале запуска или красная строка под корнем или адресом в «Настройки проекта»** | Строка конфига даёт путь, который не поместится на Windows (259 знаков, папка 247, имя 255), macOS (имя 255 знаков UTF-16) или Linux (имя 255 байт) при корне проекта, названном в сообщении. Запуск не блокируется; файлы, которые не поместились, пропускаются и считаются («Длинные пути: не записано N файлов зеркала»). Список строк — `kit:paths`. Сократите имя папки проекта или перенесите проект ближе к корню диска, либо включите длинные пути Windows и выполните `git config --global core.longpaths true`. Подробности — [длина путей](../../docs/connectors.md#длина-путей-проверка-при-сохранении-настроек). |
| **`sync:audit` сообщает `COLLISION`** | Две страницы различаются только регистром; зеркало дописывает id страницы. Запустите `kb:names`. |

## Агент

| Симптом | Причина и что делать |
|---|---|
| **«все провайдеры роли недоступны» / шаг «ждёт связь»** | Проверка соединения знает: профиль провайдеров или интернет лежит. Вызов не ушёл, в карантин никого не посадили, шаг маршрута ждёт сам (разовый вызов отказывает с причиной). Продолжится, когда связь вернётся; «Проверить сейчас» будит. Если VPN поднят, проверьте «Проверку ручки провайдера» в *Моделях → провайдер* (путь и ключ). |
| **«не ответил» / пустой ответ** | `agent:ping` проверяет цепочку; `agent:probe` отличает «нет связи» от «неверный ключ» и «нет такой модели» и перечисляет модели шлюза. |
| **Три сбоя подряд, прогон останавливается** | Так задумано: виноват шлюз, а не карточки. Почините шлюз и запустите снова — остальное подхватится. |
| **Очень медленно, по одному запросу** | `agent:width` измеряет, сколько параллельных запросов держит шлюз; задайте `…_WIDTH`. |
| **Утверждение в тезисе «без опоры»** | Момус ничего не нашёл в источнике. Оно перечислено в `ops:todo`; `agent:distill --recheck` проверит ещё раз. |

## База

| Симптом | Причина и что делать |
|---|---|
| **«папки верхнего уровня вне схемы»** | Перенесите содержимое в `Workspaces/<задача>/`, либо закройте папку в `.gitignore`, если это служебные данные, либо объявите её в `aurora.config.yaml` → `paths.extra_structure_dirs`. |
| **Коммит не проходит на храповике** | Число ошибок линтера выросло выше базовой линии. Почините (`kb:repair`) — либо осознанно `AURORA_SKIP_RATCHET=1`. Он снимает только храповик; проверку сообщения коммита не снимает ничто. |
| **Сотни битых ссылок после разбора** | Ссылки на карточки, которых пока нет: `kb:repair --links`, затем `--stubs`. |
| **Источник помечен разобранным, а карточек нет** | `kb:build --reopen --apply`. |
| **Один источник, одна карточка на 60 КБ текста** | Разбор оборвался рано: `kb:build --thin`. |
| **Одна сущность живёт пятью карточками** | `kb:twins`, `agent:twins`. |
| **Доля `knowledge` низкая** | Либо задачи ещё в работе, либо связей не нашли. Трассировка (`ops:trace-table`) и `trust_statuses` в конфиге. |
| **«источник пропал» на карточке** | Страницу перенесли или удалили: `kb:repair --gone-sources`. |
| **Имя файла не проходит на Windows или macOS** | `kb:names` (предпросмотр, затем `--apply`). |
| **Кириллическая папка под `.gitignore` помечена как вне схемы** | Исправлено в 1.148.2; обновите движок (`kit:update`). |

## Вложения и расшифровки схем

Что значат строки `kb:ingest-office` (и те же строки в итоге прогона, плане и `kit:doctor`).

| Симптом | Причина и что делать |
|---|---|
| **«Без транскрипта (текста слишком мало — логотип, иконка, пустая схема)»** | В файле меньше 200 знаков текста (80 для схемы и изображения): логотип, иконка, пустая схема. Это не ошибка. Команда запоминает хеш файла в `Raw/Extracted/.skipped.json`, и повторный запуск с доктором его не трогают; изменённый файл пробуется снова, `--force` пробует все. |
| **«Не разобраны: нет транскрипта — N»** в плане разбора или предупреждение `kit:doctor` «без транскрипта» | У документа, вложения или схемы нет актуального транскрипта: команду не запускали после синка, файл отрезал потолок за запуск, либо нет подходящего конвертера. Запустите `kb:ingest-office`; план называет файлы, поэтому молча ничего не пропадает. |
| **«Документов низкого качества: N»** | Текст получился пустым или нечитаемым (скан без распознавания, сломанная кодировка, повторяющиеся знаки). У такого транскрипта `quality: low`, в разбор он не идёт. Исправьте оригинал либо настройте кольцо распознавания (*Модели* → OCR) и запустите `kb:ingest-office --force`. |
| **«Отложено до следующего запуска (потолок файлов за запуск — N)»** | Достигнут потолок вложений и схем за один запуск; считаются записанные транскрипты. Запустите команду ещё раз либо поднимите «Потолок файлов за запуск» в «Настройках проекта» → «Извлечение из вложений». |
| **«Дубликаты по содержимому»** | Один и тот же файл приложен к нескольким страницам; на всех один транскрипт. Делать нечего. |
| **«Длинные пути: имя транскрипта сокращено до хеша»** | Путь транскрипта не уложился в 200 знаков, и его имя стало хешем; полное имя вложения остаётся в шапке (`attachment`). Чтобы имена читались, сократите заголовки страниц или путь проекта ([длина путей](../../docs/connectors.md#длина-путей-проверка-при-сохранении-настроек)). |
| **«Изображения без текста: распознавание не настроено»** | Переключатель «Распознавать изображения моделью» включён, а в кольце распознавания нет модели. Задайте модель в *Модели* → OCR либо выключите переключатель. Это предупреждение, шаг остаётся зелёным. |
| **«пропущено (больше предела размера вложения)»** | Файл больше `attachment_max_mb` — того же предела, что у синка. Поднимите его в форме проекта, если документ нужен. |
| **«нет подходящего конвертера»** | Ни встроенное чтение, ни `pandoc` / `markitdown` формат не берут (например, pptx без них). Строка называет файл; поставьте конвертер ([INSTALL](../../docs/INSTALL.md)) или сохраните файл в docx / pdf. |
| **Отказ с упоминанием DOCTYPE или ENTITY либо «вложенность XML больше N»** | Файл небезопасно читать: документ или схема объявляет внешние сущности или собрана как бомба. Отказ намеренный, файл не переводится; возьмите содержимое из исходного редактора. |

## Установлено, но не для вас

Корпоративный ноутбук: на странице **Установка** всё зелёное, а при обработке базы всплывает полоса «Pydantic AI выбран, но вызовы идут мимо». Обычно это значит, что Pydantic AI стоит, но у другой учётной записи. Панель однажды запустили «от имени администратора» под отдельной админской записью, и venv лёг в её профиль. Под вашей обычной записью его нет.

Шапка **Установки** говорит, для кого идёт проверка: «Проверено для: пользователь · домашняя папка … · права: обычные / администратор». Строка Pydantic AI пишет «работает для вас» только тогда, когда адаптер действительно поднялся (ответил «готов») так же, как в прогоне выбранного проекта: тот же запуск, то же окружение, тот же файл адаптера из `.aurora/scripts/agents/`. Ответ хранится в памяти панели до **Проверить снова** или до установки.

| Симптом | Причина и что делать |
|---|---|
| **Жёлтая полоса «Панель запущена от имени X / с правами администратора»** | Всё, что вы поставите из этой панели, ляжет в профиль X и не будет видно, когда вы откроете панель обычным способом. Закройте её и откройте без «Запуск от имени администратора», под своей учётной записью. Права администратора для установки не нужны. |
| **«Pydantic AI 2.57.0 стоит у пользователя X (поставлен …) в … — для вас (Y) он недоступен»** | Каждая установка из панели или из терминала оставляет запись в общей папке машины: `%ProgramData%\AuroraStudio\installs\` (Windows), `/Users/Shared/AuroraStudio/installs/` (macOS), `/var/tmp/aurora-studio/installs/` (Linux). Строка показывает чужую установку. Себе поставьте кнопкой **Установить** у Pydantic AI: она ставит в вашу домашнюю папку. Из терминала в папке проекта: `python .aurora/scripts/agent_core.py --venv-install`. |
| **«Версия видна, но для вас не запускается: …»** | Пакет в venv есть, а процесс адаптера не поднимается. Строка называет точную причину. `venv … построен на Python другого пользователя или на Python, которого больше нет`: venv создан Python'ом из чужого профиля или Python потом удалили; поставьте для себя кнопкой **Установить**. `процесс адаптера завершился сразу при запуске`: venv повреждён, переустановите. |
| **«В окружении задана PYTHONPATH — для venv движок её снимает»** | PYTHONHOME и PYTHONPATH, которые корпоративное окружение задаёт для своего Python, в процессы venv (адаптер, graphify, pip) не передаются. Это сведение, а не ошибка: делать ничего не нужно. |
| **«venv … принадлежит другому пользователю или закрыт на запись»** (macOS, Linux) | venv ставили через `sudo`: он работает, но обновить его без прав владельца нельзя. Удалите `~/.aurora/venv` с правами владельца (`sudo rm -rf ~/.aurora/venv`) и поставьте заново из **Установки** без `sudo`. |
| **Пакет Python не ставится: нет прав на папку пакетов** | Python поставлен для всех пользователей, а вы без прав администратора. **Установка** показывает команду с `--user`, и кнопка ставит так же, в вашу папку пользователя. |
| **git или pandoc на Windows без прав администратора** | `winget install --id Git.Git -e --scope user` и `winget install --id JohnMacFarlane.Pandoc -e --scope user`: у обоих пакетов в winget есть установщик для пользователя. |

В красной полосе и в итоге прогона про это одна фраза: «у другого пользователя этой машины есть установка (запись от …)». Имени и пути там нет, потому что итогом и журналом делятся. Кто именно поставил, видно только в **Установке**. То же печатают `kit:doctor` и `python .aurora/scripts/agent_core.py --venv-status`.

## Трекер задач и вики

| Симптом | Причина и что делать |
|---|---|
| **«роль «tasks» объявляют несколько коннекторов»** | Трекером задач (или вики) могут быть два установленных коннектора, а проект не выбрал. «Настройки проекта» → «Трекер задач и вики»: выберите один и сохраните. |
| **«коннектор «…» не настроен»** | У трекера или вики нет адреса сервера в настройках проекта (`atlassian.jira.base_url` у Jira, `atlassian.confluence.base_url` у Confluence). Заполните его в «Настройках проекта». |
| **«входа нет или сервер его не принял»** | На этой машине нет ключа (`JIRA_PAT` / `CONFLUENCE_PAT` в файле машины `.env.aurora.local`) или сервер его отверг. Строка подробностей несёт слова сервера. |
| **«не умеет операцию … — обновите движок проекта»** | Копия коннектора в проекте старше операций: «Версия» → «Подготовить проект» (или `aurora.py update <проект> --apply`). |
| **Список типов или эпиков пуст, «списки из трекера не получены»** | Нет ключа проекта (ни у вида, ни у документа, ни в настройках трекера) или трекер не ответил. «Обновить список» спрашивает заново; иначе списки хранятся час. |
| **«Создать задачу» серая** | Трекер не выбран или не умеет заводить задачи; подсказка у кнопки называет причину. |
| **«Документ изменился на диске с момента открытия» в блоке «Задача»** | Файл правили в другом месте (редактор, публикация, git). «Перечитать» и сохранить снова. В «Файлах» сначала сохраните текст: пока в редакторе несохранённое, блок не пишет. |
| **Повторное «Создать задачу» не заводит вторую** | Так задумано: `task_key` в шапке значит, что задача есть. Чтобы завести новую, уберите из шапки `task_key` и `task_url`. |

## Панель

| Симптом | Причина и что делать |
|---|---|
| **«движок отстаёт от кита»** | **Версия** → предпросмотр → `--apply`. Маршрут не стартует в проекте, чей движок старше кита панели. |
| **Свежий клон: «движка проекта нет на этом компьютере» / «неполный»** | `.aurora/` — локальная копия движка, в git она не едет. Откройте проект в панели: она достроит `.aurora/` сама (`kit:update --engine-only`; файлы проекта и git не меняются). Не вышло — в полосе над разделами и в **Версии** есть кнопка **Подготовить проект**. Всё остальное обновление (`AGENTS.md`, шаблоны, правила `.gitignore`) остаётся за **Версия** → **Применить**. |
| **«Pydantic AI выбран, но вызовы идут мимо» (красная полоса)** | Появляется **только** при неисправности самого пути Pydantic AI, и полоса называет причину. `venv python: … не найден` — Pydantic AI не стоит на этом компьютере: **Установка** → Pydantic AI. `адаптер: .aurora/scripts/agents/… не найден` — движок проекта неполный (страница «Установка» при этом может быть зелёной): **Версия** → **Подготовить проект**. `не установлен пакет …` / `не импортируется` / `не прошёл проверку совместимости` / `процесс адаптера упал` — **Установка** → Pydantic AI (переустановить или вернуть версию). `HTTP-клиент адаптера не доходит до бэкенда №N, а проверка движка доходит` — у процесса адаптера своя сеть: сверьте `HTTP_PROXY`/`NO_PROXY`, корневой сертификат шлюза (`SSL_CERT_FILE`), DNS. Все сообщения и что делать при каждом — [INSTALL](../../docs/INSTALL.md#что-значит-каждое-сообщение). |
| **«Шлюз моделей недоступен: …» (красная полоса) или строка итога «обрыв связи»** | Беда сети или шлюза, **не** Pydantic AI: полоса называет вид (DNS, отказ в соединении, таймаут соединения, нет маршрута, TLS и сертификат, прокси, сброс, ошибка сервера 5xx, ключ не принят 401/403, 404, ответ не JSON) и бэкенд. Проверьте сеть, VPN и статус шлюза; ключ и имя модели — в разделе **Модели**. Полоса появляется после трёх неудач подряд на одном бэкенде и уходит сама с первым ответом; единичный обрыв — только сведение в итоге («были повторены — это не поломка Pydantic AI»); прямой HTTP при нём не используется. |
| **«Сертификат сервера не прошёл проверку» (git на своём сервере с корпоративным самоподписанным сертификатом); «Доверять» нажато, а ошибка возвращается** | «Настройка» вкладки Git (или «Подключить по строке git clone», или «Из git-репозитория» при создании проекта) → **Доверять сертификату сервера…**, сверьте отпечаток SHA-256 с администратором, подтвердите. С 1.187.6 доверие запоминается на этом компьютере по адресу сервера (`~/.aurora/git/certs/<сервер>_<порт>.pem`), действует и у проекта без git, а `GIT_SSL_CAINFO` для этого сервера не мешает; проверка остаётся включённой. На более ранней версии доверие у проекта без git не сохранялось — обновите кит и нажмите ещё раз. Git for Windows со схемой schannel: `git config --global http.sslBackend openssl`. |
| **После обновления страница показывает старый интерфейс** | Перезапустите панель (`aurora_cockpit.py --restart`); первый запуск новой версии пересобирает реестр команд и может занять минуту. |
| **Порт занят** | `--port 9000` или `--restart`, чтобы заменить работающую панель. |
| **macOS блокирует `start-aurora.command`** | Правая кнопка → *Открыть*. |

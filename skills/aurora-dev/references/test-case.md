# TC-000 · Короткое утверждение о поведении

## Зачем этот кейс

Одно-два предложения: какая ошибка возможна и чем она опасна. Не «проверить работу
команды», а «команда отмечает источник разобранным, хотя карточек не появилось — прогресс
растёт, знание нет». Кейс без ответа на «зачем» через полгода никто не поймёт и удалит.

## Предусловия

Состояние, которое должно быть создано **до** первого шага. Каждое — проверяемое, без
«система настроена»:

- проект развёрнут, `aurora.config.yaml` содержит `verify.trusted_sources: [Raw/contract]`;
- в `Sources/Confluence/Страница.md` лежит файл с тремя заголовками второго уровня;
- база пуста: `AuroraKnowledgeDB/Concepts/` не содержит `.md`.

## Тестовые данные

Точные значения, а не «любой файл». Если данные длинные — положить рядом в `cases/data/`
и сослаться. Данные должны быть обезличенными: имена вымышленные, домены `example.com`.

| Что | Значение |
|---|---|
| источник | `Sources/Confluence/Страница.md`, 3 секции, 1200 символов |
| карточка | `AuroraKnowledgeDB/Concepts/Понятие.md` со `source:` на эту страницу |

## Шаги

Один шаг — одно действие и одно наблюдение. Команда пишется целиком, как её вводят.

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `python3 .opencode/scripts/build_plan.py --done Sources/Confluence/Страница.md` | код возврата `1`; в stderr строка «отметка не поставлена»; `meta/manifest.json` не изменился |
| 2 | создать карточку с `source: "Sources/Confluence/Страница.md"` | файл появился |
| 3 | повторить шаг 1 | код возврата `0`; в stdout «обработан, карточек 1»; в `manifest.json` запись с хешем и датой |

## Критерий прохождения

Кейс пройден, когда **все** ожидания шагов выполнены. Формулировать так, чтобы результат
проверялся машиной, а не мнением: код возврата, наличие подстроки, существование файла,
значение поля. «Работает корректно» — не критерий.

## Что считается провалом

Отдельно перечислить то, что легко принять за успех: команда завершилась нулём, но файл
не создан; вывод похож на нужный, но число другое; изменения записаны при dry-run.

## Откат

Как вернуть окружение в исходное состояние: `git checkout -- AuroraKnowledgeDB`, удалить
временный проект, снять хук. Кейс, после которого нельзя запустить следующий, — плохой.

## Заметки для ассистента

- сверяй **точные** строки вывода, а не смысл: формулировки в скриптах менялись, и
  проверка «по смыслу» пропускает регрессию;
- при расхождении не правь ожидание в кейсе — сначала выясни, кто прав: код или кейс;
- если кейс закрыт автотестом, укажи его в поле `automated:` и не выполняй руками.

# TS-000 · Маршрут целиком

## Что проверяет сценарий

Кейс проверяет одну команду, сценарий — **стык между ними**: что выход одной команды
годится на вход следующей, что состояние переносится, что человек доходит до результата
не застревая. Ошибки стыка не ловятся кейсами по определению: каждая команда по
отдельности работает.

## Исходное состояние

Точка старта, одинаковая при каждом прогоне:

- чистый проект из `aurora.py new` либо `git checkout` на известный коммит;
- зеркала не выгружены, база пуста, `manifest.json` отсутствует.

## Маршрут

Нумерованные шаги с указанием, **чем заканчивается каждый** — это точка синхронизации:
если состояние после шага не то, дальше идти бессмысленно.

### Шаг 1 · Зеркало

```bash
python3 .opencode/scripts/confluence_export.py --force
```

Состояние после: в `Sources/Confluence/` файлы, `sync_state.md` заполнен, `sync:audit`
не показывает MISSING.

### Шаг 2 · Разбор

```bash
python3 .opencode/scripts/build_plan.py --slice Sources/Confluence/<файл>
python3 .opencode/scripts/build_plan.py --card "Имя" --source Sources/Confluence/<файл> \
    --sections 1,2 --to Concepts --apply
python3 .opencode/scripts/build_plan.py --done Sources/Confluence/<файл>
```

Состояние после: карточка в базе, запись в `manifest.json`, источник исчез из плана.

### Шаг 3 · Приёмка

```bash
python3 .opencode/scripts/kb_verify.py --auto --apply
```

Состояние после: у карточки `status: verified`, заполнены `verified_basis` и
`verified_hash`.

## Развилки и что делать

Сценарий описывает не только счастливый путь. Для каждой развилки — признак и выход:

| Развилка | Признак | Куда идти |
|---|---|---|
| источник без структуры | `--slice` печатает «секций: 0» | разбирать чтением, шаг 2 вручную |
| карточка не принята | в отчёте «не подошло ни под одно правило» | это норма для новых историй — не ошибка сценария |
| битые ссылки | `kb:verify` пропускает карточку | `kb:repair --links --apply`, вернуться к шагу 3 |

## Критерий прохождения

Сценарий пройден, когда достигнуто конечное состояние **и** ни один шаг не потребовал
действий, которых нет в маршруте. Обход руками — это провал сценария, даже если результат
получен: значит инструмент не доводит до цели сам.

## Что фиксировать в прогоне

Каждый прогон — файл в `runs/YYYY-MM-DD_TS-000.md`: версия движка, кто гонял, результат
по шагам, найденные расхождения со ссылками на заведённые задачи. Прогон без записи
считается непроведённым.

## Заметки для ассистента

- выполняй шаги строго по порядку и не «чини» окружение молча: обход руками — находка,
  а не помеха, её надо записать;
- после каждого шага проверяй заявленное состояние, а не только код возврата;
- если шаг требует решения по смыслу (назвать карточку, выбрать раздел) — прими его,
  но запиши, чем руководствовался: сценарий должен воспроизводиться другим человеком.
